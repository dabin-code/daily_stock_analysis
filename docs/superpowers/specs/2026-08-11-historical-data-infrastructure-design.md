## 一、背景

对生产库 `data/stock_analysis.db` 的实测暴露出多类缺陷。其中成交量单位问题已作为独立热修交付（见 1.2），其余构成本项目的范围。

### 1.1 复权体系完全缺失，生产因子跨除权日失真

| 项目 | 实测值 |
| --- | --- |
| `adj_factor` 取值 | `exactly_1.0` 2,604,244 行 / `NULL` 354,025 行，**无一行真实因子** |
| `adj_factor_source` | `legacy_assume_one` 2,604,099 / `NULL` 354,025 / `fetcher_unset` 145 |
| `adj_anchor_date` | **0 行非空** |
| 不复权价列 | **不存在** |

对 8 只老股票逐日核验「由 `close` 推算的涨跌幅」与表内 `pct_chg`，561 个交易日中仅 0–5 天不一致，
不一致日集中于 6–7 月（平安银行 2024-06-14、贵州茅台 2024-06-19 与 2025-06-26、
工商银行 2024-07-16、招商银行 2026-07-10）。

初步口径判断：`close` 为不复权真实盘口价（Tushare `daily` 原生口径，120 积分档为
「非复权日线数据」，`_apply_qfq_adjustment()` 因 `adj_factor` 接口受限而回退）；
`pct_chg` 为复权口径，故除权日与 `close` 打架。

**该结论的证据强度不足以直接作为全库地基，必须先做全表口径校验（阶段 D）。** 反证已经出现：
1.2 的单位修复中发现 397 条记录的 `amount ÷ 股数` 恰为 `close` 的约 2 倍
（如 `300394` 2024-04 至 05 连续多日），这与「`close` 是复权价而 `amount` 是原始值」相符，
说明库内至少存在局部的复权价混入。

#### 全表分源实测（2026-08-11，阶段 D 的先验输入）

对 `close(prev) × (1 + pct_chg/100)` 与 `close(t)` 逐行比对，按 `data_source` 分组：

| data_source | 行数 | 平均相对误差 | 偏差 > 1% 的行数 | 断裂率 |
| --- | --- | --- | --- | --- |
| TushareFetcher | 2,062,693 | 2.93e-4 | 5,951 | **0.29%** |
| TushareFetcher(bulk) | 514,160 | 3.63e-4 | 1,795 | **0.35%** |
| EfinanceFetcher | 380,485 | 3.2e-5 | 102 | **0.027%** |
| BaostockFetcher | 658 | 9.3e-5 | 2 | 0.30% |

**两条关键推论：**

1. Tushare 两路径的断裂率 0.29%/0.35% 与理论预期高度吻合——库内每股约 531 个交易日、
   年均约 1 次除权，预期断裂率为 `2 / 531 ≈ 0.38%`。这**支持**「Tushare 的 `close` 为不复权价、
   `pct_chg` 为复权口径」的判断，断裂日即除权日。
2. **Efinance 的断裂率低一个数量级（0.027%），与「其 `close` 为前复权价」相符**——
   复权价下该恒等式在除权日同样成立，故不产生断裂。

因此库内**复权口径按数据源混存**，而非全库统一。这比单一口径错误更棘手：
跨源拼接的个股序列会在数据源边界产生伪跳空。阶段 D 必须按
`(data_source, 年份)` 二维定位口径边界，而不是只判断「全库是不是复权价」。

**生产缺陷：** `FactorService` 的均线、动量、突破比全部基于未复权 `close`，
跨除权日会产生虚假跳空。A 股分红集中于 6–7 月，即**每年 6–7 月全市场技术因子集体失真一次**。

### 1.2 成交量/成交额单位混存（已独立修复，此处仅登记）

三条写入路径把数据源原生单位原样写入：Tushare `daily` 的 `vol` 为手、`amount` 为千元，
efinance 成交量为手，而 `stock_daily` 的口径是股与元。296.4 万条可判定记录中
110.0 万条（37.1%）单位错误，量比等因子在数据源边界出现 100 倍级断层。

已于本次交付前修复：写入侧统一走 `data_provider/base.py` 的 `lots_to_shares()` /
`thousand_yuan_to_yuan()`，存量由 `scripts/repair_volume_amount_units.py` 修正，
全部数据源的成交均价/收盘价中位数已回到 1.00 附近。

**对本项目的意义有二**：一是它证明「同一张表内不同写入路径口径不一致」在本仓库是已发生的事实，
因此阶段 D 的全表口径校验不可省略；二是它留下的 397 条带外记录是 1.1 中复权价混入的直接线索。

### 1.3 样本期不足以支撑统计推断

`stock_daily` 覆盖 2024-04-18 至 2026-08-07，共 560 个交易日，2024-09-01 之前仅 93 个。

回测样本双重不独立（时间重叠 + 横截面相关），有效样本量约等于
`可用交易日数 ÷ 持有天数`。扣除因子预热与末端缓冲后当前可用约 270 个交易日，
持有 20 日时有效观测约 13 个。

更关键的是**市场环境覆盖**：现有数据基本只含 2024 年 9 月后的普涨行情。
五层策略的第一层是市场环境判定（L1），若数据中只存在一种市场环境，
L1 在回测中无变化可言，**在原理上无法被验证**。

### 1.4 无市值数据

全库无市值、流通股本字段，`daily_basic` 接口零调用，回测的风格中性化对照组无法构造。

### 1.5 `list_date` 失真，状态字段无历史版本

- `instrument_master.list_date` 5489 条中 5080 条（92.5%）等于该股在 `stock_daily` 的首根
  K 线日期。贵州茅台（2001 年上市）记为 `2024-04-19`。根因是
  `TushareFetcher.get_stock_list`（`tushare_fetcher.py:650-654`）的 `fields` 未请求 `list_date`。
- `listing_status='delisted'` 仅 7 条，根因是同一处写死 `list_status='L'`。
- **`listing_status` 与 `is_st` 是时变属性但只有当前快照。** 用今天的状态筛 2018 年的样本属
  point-in-time 违规。

### 1.6 指数与板块热度历史缺失

- `stock_daily` 仅有 `sh000001` 464 条。`scripts/fast_backfill.py:241` 将指数落库变量写死为空，
  且 `main()` 从未调用已定义的 `fetch_index_daily`（106 行）。
- `daily_sector_heat` 仅覆盖 2026-03-02 起 57 个交易日。

### 1.7 Tushare 权限实测

当前 token 为 **120 积分免费档**。实测 `daily` 可用（全市场 5535 行/1.44s，
2018-01-02 可取 3282 行）；`adj_factor`、`daily_basic`、`stock_basic`、`index_daily`、
`trade_cal`、`dividend` 全部返回频率超限。

### 1.7b 实测审计结论（2026-08-11，开发前最终审计）

以下数字来自实际运行，不是估算，构成本设计若干条决策的直接依据。

| 观测 | 数值 | 支撑的决策 |
| --- | --- | --- |
| 000001 / 2024-06-14 原价涨跌幅 | **−5.7407%** | 除权假断层的量级 |
| 同日实际经济收益 | **+0.9921%** | 二者相差 6.73 个百分点 |
| 同日 raw MA20 相对正确尺度的偏差 | **6.7939%** | **J 阶段不可省略**（6.7） |
| 百股隔离重放 | **全部 fail-closed，因指数历史不足** | 证实 5.6 的指数读取源为硬阻断 |
| 500 股单日因子耗时 | **14.822 秒** | 全期串行外推约 **82.4 小时**，见回测设计 11.3 |
| 100 股因子快照 `circ_mv` | **非空但恒为 0** | 见 7.4，真实换手率尚未接入 |
| 创业板 15% 涨幅 | **被默认主板规则判为涨停** | 见 5.8，误判是**双向**的 |

`raw MA20 偏差 6.79%` 这一项尤其关键：它把「除权失真」从一个定性论断变成了可度量的量。
均线偏差近 7% 意味着所有以均线为基准的比率型因子（乖离、突破比、支撑位距离）
在除权日附近全部失真同等量级，而这类因子正是五层策略 L4 买点判定的主要输入。

### 1.8 休眠的 qfq 引信：购买积分本身会翻转生产写入语义

`tushare_fetcher.py:438-529` 的 `_apply_qfq_adjustment` 在常规取数路径
（`:424`）上被调用，把 `daily()` 的不复权价转为前复权，`:522-523` 明确包含 `pre_close`。

**它目前是休眠的**：`:485-492` 捕获「频率/权限/积分」类错误后进入一小时熔断并回退不复权，
而 120 积分档恰好稳定触发该分支。1.1 的分源实测印证了这一点
（Tushare 两路径断裂率 0.29%/0.35%，为不复权特征）。

**买到 5000 积分的瞬间 `adj_factor` 变为可用，该函数会自动生效**，
生产写入从不复权静默翻转为前复权。这与本设计的全部前提相反，且触发时点在阶段 H，
彼时 C–F 已验收完毕，等于在验收之后重新污染。

三处具体危害：

1. `:512-513` 锚定「窗口内最新交易日」——锚点随抓取窗口漂移，
   同一天的数据不同批次抓取得到不同尺度，正是 `storage.py:104-121` 所警告的问题。
2. `:527` 四舍五入到 2 位小数，破坏 6.3「复权价按 double 存储」的精度要求。
3. `:452` 同时调整 `pre_close`——一旦与 P0-2 的 `pre_close` 持久化叠加，
   落库的 `pre_close` 将是复权后的值，6.2 的 `ratio` 公式会静默失效且难以察觉。

**附带事实**：CHANGELOG 记录该函数是为修复 001229 除权导致的假底背离信号而加，
但它从未真正生效——**那个缺陷至今是活的**，与 1.1「每年 6–7 月全市场技术因子集体失真一次」
的结论一致。处置见 9.6。

## 二、目标

1. A 股日线回补至 2018-01-01，覆盖熊市、结构性牛市、震荡下跌、反弹四种环境。
2. 建立可信复权体系：保留不复权真实价，提供不含未来信息的复权价。
3. 修复生产因子跨除权日失真。
4. 补齐历史市值、基准指数、真实上市日期、退市与状态时间线。
5. 数据质量可验收：每项都有具体数值门槛与**可达**的交叉校验。
6. 积分依赖可降级，且降级必须显式。

## 三、非目标

- 不为退市股做补漏与质量治理（其行情随全市场按日拉取天然入库，见 5.5）。
- 不建设板块成分股历史版本快照。
- 不迁移数据库后端（SQLite 继续使用，见 12.2）。
- 不改动选股策略逻辑本身，只改因子的输入数据口径与数据获取层。
- 不覆盖港股与美股。

## 五、数据缺口与处置

### 5.1 历史日线回补至 2018

- 接口：`daily(trade_date=)`，**120 积分即可**，每次返回全市场约 5000 行。
- 调用量：约 2080 个交易日 → 约 2080 次调用，低于免费档 8000 次/日上限。
- **必须全窗口重取，包含已有的 561 天**：现有数据没有 `pre_close`，而复权体系完全依赖它。
  重取以 `INSERT OR REPLACE` 幂等覆盖。见 9.1 的续跑语义改造。
- 单位换算复用 1.2 已落地的 `lots_to_shares()` / `thousand_yuan_to_yuan()`。

### 5.2 交易日历（扩展既有模块，不新建）

复权重建、缺口判定、审计期望域都依赖「真正的前一交易日」。若仅从行情数据反推日历，
**全市场同日缺失的情形无法被发现**。

仓库已有 `src/core/trading_calendar.py`（基于 `exchange_calendars`，
已在 `requirements.txt`，`FastBackfillService` 正在使用）。本项目**扩展它而非新建平行实现**：

- 新增 `prev_session(market, d)` 与会话序列查询，由持久化表 `trading_calendar` 支撑。
- 建表数据源：akshare `tool_trade_date_hist_sina`（免费）为主，
  `exchange_calendars` XSHG 作为第三方对照，二者差异必须归零后才允许建表完成。
- **既有 `is_market_open()` 的 fail-open 行为保持不变**（`trading_calendar.py:79-90` 在
  依赖缺失、市场未知、任何异常时均返回 True，现有调用方依赖该语义）。
  复权与缺口判定改用新增的 fail-closed 接口 `require_session(market, d)`，
  数据不可得时抛错而非放行。两种语义并存但入口不同，不改变现有行为。

### 5.3 复权因子与复权价

两个来源，对应 6.0 的双层口径：

- **权威层** `adj_factor(trade_date=)`，**需 2000 积分起**，调用量约 2080 次。
  Tushare 自产的后复权因子，历史段一次性拉取后永久留存。
- **事实层**由 5.1 落库的 `pre_close` 按第六节计算，纯本地计算，无额外抓取成本，
  且积分到期后仍可持续用于每日增量。

### 5.3b 除权除息事件明细

- 接口：`dividend`，**需 2000 积分起**。
- 用途：验收 #5 的权威事件信源，取代完整性未知的 akshare 分红送配。
- **这是购买积分的次要动机**：它把「外部信源完整性未知」这一残留风险从设计中移除，
  使验收 #5 的门槛可以直接定为 100% 匹配，而非「先实测再定门槛」。

### 5.4 历史市值

- 接口：`daily_basic(trade_date=)`，**需 2000 积分起**。
- **单位**：`total_mv`、`circ_mv` 为**万元**，落库统一为元。
- 调用量：约 2080 次。
- **不可替代**：akshare 仅有当日快照，无历史市值序列。这是**唯一无免费替代**的项，
  也是购买积分的首要动机。注意 5000 档才「无总量限制」，2000 档存在总量上限，
  而本项需拉取约 1040 万行。

### 5.5 上市日期、退市与状态时间线

- 接口：`stock_basic`，`fields` 扩展为
  `ts_code,name,list_date,list_status,delist_date,market,industry`，
  分别以 `list_status='L'/'D'/'P'` 调用三次。
- **免费降级可用且优先**：baostock `query_stock_basic` 免费返回 `ipoDate`/`outDate`/`status`，
  现有 `BaostockFetcher.get_stock_list`（`baostock_fetcher.py:341,354`）已拿到含这些字段的
  DataFrame 却只 `return df[['code','name']]`，改动量极小。
  因此上市/退市日期归入**免费阶段 G1**（见第八节），不必等待积分。
- **退市股行情天然入库**：`daily(trade_date=)` 返回该日**在市**的全部股票，含此后退市者。
  因此写入路径**不得**按当前 `instrument_master` 做白名单过滤，否则会静默丢弃退市股历史行、
  使幸存者偏差原地复发。同批次须把历史 code 与 `delist_date` 补进 `instrument_master`。
- **ST 与行业时间线**：**本期重建**（阶段 G2）。原计划不做，
  但回测的历史重放要求时点正确的 ST 与行业，且 ST 还决定涨跌停阈值（±5% vs ±10%），
  故提级为本期必做。数据源与 `namechange` 的规避要点见 9.5。
  审计期望域仍**不使用 ST 条件**（见 9.2），二者互不依赖。

### 5.6 基准指数

- 接口：`index_daily(ts_code=)`，**需 2000 积分起**，单次最大 8000 行。
- 标的：`000300.SH`、`932000.CSI`、`000905.SH`、`000852.SH`、`399006.SZ`、`000001.SH`。
- 降级：akshare `stock_zh_index_daily` 免费可拉（`market_guard.py:48` 已在使用）。
- **存量 `sh000001` 464 行采用双写并存 + 读取开关**，不做不可逆删除（见 12.1）。
  L1 市场环境判定的读取源切换属用户可见行为变化，须带开关并做切换前后对比。

#### 读取源切换是硬阻断，不只是「双写并存」（v6 修正）

v5 只说了「双写并存 + 读取开关」，没说清楚**谁在读旧源、切换后会怎样**。实测：

- 指数当前作为一个普通 `code` 存放在 `stock_daily` 表中。
  `bottom_divergence_v2_dataset.py:240` 把 `market_guard_index` 直接并入 `stock_codes`
  一起从 `StockDaily` 复制；`bottom_divergence_v2_replay.py:874-878` 用
  `repository.get_range(index_code, ...)` 从同一张表读取。
- 默认值为 `sh000001`（`config.py:699`）。
- **该 code 在库内仅 464 行**——不仅覆盖不到 2018–2023，
  连 2024–2026 的 561 个交易日都缺 97 天。

因此历史重放跑 2018–2023 时，L1 市场环境**完全无数据**。
这不是精度问题而是可行性问题：**读取源不切换，回测项目无法进行**。

切换须同时覆盖三处：生产实时路径（`screening_task_service.py:373-375` 经
`fetcher_manager` 实时取数）、重放路径（读库）、以及隔离回放的表复制清单（见 9.7）。
生产与重放本就不同源，切换时须一并对齐，否则「重放结果」与「实际决策」不可比。

### 5.7 板块热度历史

不在本项目范围。由回测管线按交易日正序滚动计算，
写入**物理隔离的临时库**（复用 `bottom_divergence_v2_dataset.py:212` 的
`isolated_replay_database`），不污染生产 `daily_sector_heat`。

注意 `daily_sector_heat` 唯一键为 `(trade_date, board_name)`，**无 scope/run_id 列**，
写入为先删后插（`storage.py:3689-3696`），因此不存在「命名空间隔离」这一选项。
此处仅登记依赖关系，方案选择见回测设计 6.2。

### 5.8 每日涨跌停价格（v5 新增）

- 接口：`stk_limit(trade_date=)`，**需 2000 积分起**，单次最多 5800 条，总量不限。
- 调用量：约 2080 次。
- 输出：`up_limit`、`down_limit`，另带 `pre_close`。

**为什么必须查表而不能靠规则重建**：涨跌停规则本身随时间变化，
仅把 ST 状态历史化并不足以重建。现有 `limit_pct_resolver.py` 的注释已自陈该缺陷：

> 创业板 only moved to ±20 % on 2020-08-24. Pre-cutover bars were ±10 %.
> This resolver does not currently take `trade_date` so it always returns ±20 % for 300/301;
> callers backtesting pre-2020-08 data must handle this themselves.

其规则表标题为「effective 2024+」，对 2018–2026 回测的错误面包括：
创业板 2018-01 至 2020-08 全段（返回 ±20% 而实际 ±10%）、
科创板 2019-07 前不存在、北交所 2021-11 前不存在，另有新股上市首日与退市整理期规则未覆盖。

#### 误判是双向的（v8 实测修正）

v7 只描述了**漏判**方向（创业板 2018–2020 按 ±20% 判定，真实 ±10% 涨停不被识别）。
实测审计发现了相反方向的**误判**：

> 创业板 15% 涨幅当前被默认主板规则（±10%）判为涨停。

即 `resolve_limit_pct` 在实际调用中根本没走到 `300/301 → ±20%` 分支，
而是落到了 `DEFAULT_A_SHARE_LIMIT_UP_PCT = 10.0` 的兜底（`:108-109`）——
说明板块解析（`market` 或 `exchange` 入参）在该路径上未正确传入。

两个方向同时存在，后果不同且互相抵消不了：

| 方向 | 触发条件 | 后果 | 对收益统计的影响 |
| --- | --- | --- | --- |
| 漏判 | 走到 300/301 分支，返回 ±20%，历史真实为 ±10% | 真涨停不被识别 | 保留了买不到的样本，**偏乐观** |
| 误判 | 板块解析失败，兜底 ±10%，实际为 ±20% | 15% 的正常涨幅被当作涨停 | 剔除了买得到的强势样本，**偏悲观** |

**因此不能声称偏差方向统一乐观**——这修正了回测设计 v6 §11.2 的表述。
净方向取决于两类样本的相对数量，在接入 `stk_limit` 之前**不可知**。

这也让「规则重建」的方案更站不住：它不仅规则本身时变，
连当前实现的板块解析都不可靠。查表是唯一出路。

- **回测侧改读 `daily_price_limit` 查表，不做规则重建。**
- `limit_pct_resolver` 保留用于生产实时路径，但**板块解析失败兜底到 ±10% 这个行为本身需要复核**——
  它在生产实时路径上同样会把创业板正常涨幅误判为涨停。该项作为独立缺陷登记，不并入本项目。
- 附带收益：`stk_limit` 的 `pre_close` 可作历史段 `pre_close` 的独立交叉校验源。

### 5.9 停复牌历史（v5 新增）

- 接口：`suspend_d(trade_date=)`，**需 2000 积分起**。
- 调用量：约 2080 次。
- 输出：`suspend_type`（S 停牌 / R 复牌）、`suspend_timing`（日内停牌时段）。

**填补 v4 的一个空洞**：6.2 的 `gap_bridged` 状态要求「缺口已归因为停牌」，
但 v4 从未指定归因的数据源，实际是无源可依的假设。有了 `suspend_d`，
缺口归因才有权威依据，`unverifiable` 的占比也才可控。

同时供回测侧判定「持有期内停牌」（回测设计 7.3）。

## 六、复权体系设计（核心）

### 6.0 双层口径：历史段权威源 + 增量段自持方法

购买 5000 积分后 `adj_factor`（2000 积分起）可用，它是 Tushare 自产的后复权因子序列。
但积分为三天时效，到期后无法继续调用——**而积分只限制 API 调用，不限制数据留存**，
窗口内拉取的历史数据永久可用。

因此复权体系分两段，且两段必须在重叠区互相验证：

| 段 | 主口径 | 校验口径 | 说明 |
| --- | --- | --- | --- |
| 历史段（2018 至积分窗口日） | Tushare `adj_factor` | `pre_close` 重建的 `adj_ratio` | 权威因子直接可用，无需递推 |
| 增量段（窗口日之后每日） | `pre_close` 重建 | — | 积分到期后唯一免费可行的方法 |

**这个结构的价值在于增量段的方法先在历史段上被完整验证过**，而不是上线后才发现问题。
重叠区的逐事件比对（见验收 #8）是本设计最强的正确性证据。

若最终未购买积分，退化为 v3 的单层结构（仅 `pre_close` 重建），
验收 #5/#8 退回免费信源并接受其完整性未知，见第十节。

### 6.1 三层数据结构

- **权威层**：`adj_factor_tushare`，Tushare 原生后复权因子，历史段一次性拉取后不再变化。
- **事实层**：`adj_ratio`，由 `pre_close` 重建的单事件除权比例，一经确认不再变化。
  历史段用于校验权威层，增量段用于延展。
- **视图层**：定点累计因子与复权价，落**独立表** `stock_daily_adj`。
  换锚点是 `DROP TABLE` + 重建，不触碰主表，也不与每日任务抢主表写锁。

权威层与事实层都落 `stock_daily` 主表，因为二者都是不可变事实。

### 6.2 `ratio` 的计算与判定

`ratio` 在历史段是**校验口径**（与 `adj_factor_tushare` 比对），在增量段是**主口径**。
两种角色下的计算与判定规则完全相同，因此历史段的校验结果可直接外推到增量段。

Tushare `daily`（120 积分即可）返回 `pre_close`，该值为**除权调整后的前收盘价**：

```text
ratio(t) = close(prev_observation(t)) / pre_close(t)
```

**`prev_observation(t)` 的定义：该 `code` 在 `stock_daily` 中 `date < t` 的最大 `date`，
即「该股自己的上一根 K 线」，而非「交易日历的上一个交易日」。**

v4 此处写作 `prev_session` 是错误的。停牌期间该股在 `prev_session` 没有行，
公式取不到值；§6.3 的递推更会让 NULL 沿链传播。实测该库 5580 只股票中
**906 只（16.2%）至少存在一个「前一交易日无行」的日期**，共 2827 个这样的日期，
回补到 2018 年后（2018–2019 重组停牌密集）比例会显著上升。

`prev_observation` 与 Tushare `pre_close` 的语义天然吻合：复牌日的 `pre_close`
就是停牌前最后一个交易日的（除权调整后）收盘价。

正常交易日 `pre_close(t)` 等于上一根 K 线收盘价，比值为 1；除权日给出除权比例。

**验证（平安银行 000001.SZ 2024-06-14）：** 前一日 close 10.80，`pre_close` 10.08，
ratio = 1.071429，反推每股派息 0.72 元。2023 年度方案为每 10 股派 7.19 元即每股 0.719 元，
对应理论除权价 10.081，交易所公布并落库为 10.08。
**因此反推值与方案值存在约 0.09% 的偏差，源于 `pre_close` 按分取整，并非精确吻合。**
该偏差方向系统性（现金分红总使 ratio > 1，取整系统性低估累计因子），按事件数线性累积。
A 股每年 1–2 次分红，8 年约 8–16 个事件，累积量级低于 1%，纳入误差预算（见 11 节 #8）。

#### 状态判定（按缺口成因分级，不是「有没有行」一刀切）

| 情形 | 状态 | ratio 取值 |
| --- | --- | --- |
| t 是该股锚点日 | `anchor` | 不参与递推，`F(a)=1` |
| `prev_observation(t)` 与 t 相邻（中间无交易日缺口），同源且 `pre_close` 有效 | `normal` | 按公式计算 |
| `prev_observation(t)` 与 t 之间存在交易日缺口，但缺口已归因（`gap_lifecycle` / `gap_flat` / `gap_bridged_confirmed`，见 6.2b） | `gap_bridged` | 按公式计算（`prev_observation` 本就是最近有数据日） |
| `prev_observation(t)` 与 t 之间存在缺口且**无法归因**（`gap_unattributed`） | `unverifiable` | 不计算，切断区间 |
| t 与 `prev_observation(t)` 跨数据源，或任一行的 `adj_convention ≠ raw` | `unverifiable` | 不计算 |
| `\|ln ratio\| > ln(3)` 且未经信源确认 | `quarantined` | 计算但不采用 |

改用 `prev_observation` 后，`normal` 与 `gap_bridged` 的**计算式统一**，
差别只在缺口是否已归因——归因决定可信度，不决定取哪一行。这比 v4 的两套取值规则更不易实现错。

**缺口归因有了权威信源**：v4 的 `gap_bridged` 要求「缺口已归因为停牌」，
但从未指定归因数据源，实际无源可依。v5 引入 Tushare `suspend_d`（见 5.9）填补该空洞。
但 `suspend_d` 需积分，而阶段 E 必须免费跑通——归因因此分两级，见 6.2b。

#### 6.2b 缺口归因的两级降级（v6 修正）

**v5 引入的依赖环**：v5 把 E 的 `gap_bridged` 归因改为依赖 `suspension_history`，
但该表由阶段 H 产出且需积分，而 E 在阶段表中标注「无积分依赖」并排在 H 之前。
这与 8 节的核心约束「D–F 必须在不依赖积分的前提下独立跑通」直接冲突。

#### v7 修正：provisional 不是「置信度低一档」，而是「不可用」

v6 把 `gap_bridged_provisional` 标为「可用，但待复核」，**这是错的**。
「停牌」与「抓取失败」的区别不是置信度差异，而是决定 `ratio` 是否有意义：

设某股在 d1、d2、d3 连续交易，而库内缺 d2。

- 若 d2 是**真停牌**：`pre_close(d3)` 就是 d1 的（除权调整后）收盘价，
  `ratio = close(d1)/pre_close(d3)` 正确给出除权比例。
- 若 d2 是**抓取失败**（该股实际交易了）：`pre_close(d3)` 是 d2 的收盘价，
  `ratio = close(d1)/close(d2)` 变成了「d2 当日涨跌幅的倒数」。
  若该股 d2 涨 8%，ratio ≈ 0.926，**会被当作一次缩股事件**。

这个伪事件会乘进累计因子并**沿递推链永久传播**——从该点起该股所有复权价都偏移 8%，
且没有任何下游检查能发现（`|ln 0.926| = 0.077` 远低于 ln 3 的隔离阈值，
也高于 0.005 的噪声地板，正好落在「看起来像真实除权」的区间）。

因此修正为：

| 状态 | 判定依据 | 阶段 | 可用于复权 |
| --- | --- | --- | --- |
| `gap_lifecycle` | 缺口由 `list_date`/`delist_date` 完全解释（未上市/已退市） | E（免费） | **可用**——权威且免费 |
| `gap_flat` | 缺口未归因，但 `\|close(prev_observation) − pre_close(t)\| ≤ 噪声地板` | E（免费） | **可用**，见下方限定 |
| `gap_unattributed` | 缺口未归因且 ratio 偏离 1 | E（免费） | **不可用**，切断区间 |
| `gap_bridged_confirmed` | `suspension_history` 命中 | E2（需积分） | 可用 |

#### `gap_flat` 豁免的成立条件与边界

当跨缺口的 ratio 落在噪声地板内时，无论缺口成因如何，**累计因子都不变**，
递推不受影响。因此该豁免对复权因子是可证的安全，而非置信度让步。

两条必须写明的限定：

1. **只对累计因子成立，不代表该区间 K 线序列完整。** 缺失的 bar 仍会影响
   因子窗口（均线、波动率、摆动点），那由 9.2 的 K 线审计与可用区间逻辑独立处置。
2. **残余风险**：一次除权恰好被反向价格变动抵消到噪声地板内，会被误判为 `gap_flat`。
   除权是离散事件、地板是 0.005 元绝对量，该巧合概率低但非零。
   实施时须统计 `gap_flat` 的数量，并在 E2 阶段用 `suspend_d` 抽样复核其中一部分，
   把实测误判率写入报告。

#### 免费模式下的实际后果

免费模式下 `gap_unattributed` 一律切断区间。实测该库 5580 只股票中
906 只（16.2%）存在至少一个缺口，其中多数应落入 `gap_flat`（除权本就稀有），
但**具体比例必须在阶段 E 实测并写入文档**，不得假设。

若 `gap_unattributed` 占比过高，说明免费模式的复权覆盖不足以支撑回测，
这是购买积分的又一个实证理由——而不是降低标准的理由。

阶段 E2 用 `suspend_d` 复核：`gap_unattributed` 命中停牌记录则升级为 `confirmed`
并重新纳入可用区间，未命中则确认为数据缺失，维持切断。

**锚点日必须显式豁免**：锚点的 `prev_observation` 必然不存在（2018-01-02 之前无数据，
IPO 股则此前尚未上市）。不豁免会导致每只股票都被自己的锚点否决。

**停牌是常态而非异常**：见上文 16.2% 的实测占比。因此必须走 `gap_bridged` 而非一律否决，
且递推必须以 `prev_observation` 为前驱。

#### 可用性是逐区间的，不是整只股票一票否决

以 `unverifiable` / `quarantined` 日为切点，把该股切成若干**可用区间**：

- 区间内正常产出复权价。
- 跨切点的因子窗口不出信号。
- 该切分结果写入 `stock_daily_adj`，供 `FactorService` 与回测侧统一读取。

这与 9.3 的当日粒度和第十节的「逐股逐区间复权可用性」一致。

#### 判定阈值

| 判定 | 规则 | 依据 |
| --- | --- | --- |
| 舍入噪声 → 归 1 | **绝对**偏差 `\|close(prev) − pre_close(t)\| ≤ 0.005` | 噪声源于按分取整，量级为 `0.005/价格`，随价格缩放；而信号（股息率）与价格无关。固定**相对**阈值会在低价股保留噪声（3 元股纯噪声约 0.17%）、在高价股丢弃信号（50 元股派 0.03 元仅 0.06%） |
| 隔离标记 | **对数**相对量 `\|ln ratio\| > ln(3)` | 乘性量上行无界、下行有界，`\|ratio − 1\|` 的对称阈值不成立。10 送 10 → ratio 2.0（ln 0.693）属正常高送转，不触发；10 转增 30 → ratio 4.0（ln 1.386）触发人工复核 |

**隔离的语义是标记而非改数。** 被隔离的事件既不归 1（会制造假崩盘）也不直接采用，
而是切断该股在该点的可用区间，直至与独立信源匹配确认。

### 6.3 累计因子与复权价

锚点为逐股的首个有效交易日 `a`。

#### 历史段：除法，不递推

Tushare `adj_factor` 本身就是锚定上市日的累计后复权因子，因此定点因子只需一次除法：

```text
F(t) = adj_factor_tushare(t) / adj_factor_tushare(a)
close_adj(t) = close(t) × F(t)
```

**这消除了 v3 递推式的全部 off-by-one 风险**——没有前后日引用，没有分区排序依赖，
没有「ratio 归属 t 还是 t−1」的歧义，缺口与停牌也不影响（每行自带因子）。

#### 增量段：递推

积分到期后，`adj_factor_tushare` 停止更新，按 `pre_close` 重建的 ratio 向前延展：

```text
F(t) = F(prev_observation(t)) × ratio(t)   -- LAG() OVER (PARTITION BY code ORDER BY date)
```

**前驱是 `prev_observation` 而非 `prev_session`**（见 6.2）。
`LAG() OVER (PARTITION BY code ORDER BY date)` 天然给出 `prev_observation`——
v4 的散文写 `prev_session` 而挂的 SQL 注释是 `PARTITION BY code`，二者自相矛盾，此处统一。

`ratio(t)` 归属于 t 而非 t−1。该递推的正确性由历史段重叠区验证（验收 #8）。

`open_adj` / `high_adj` / `low_adj` 与 `close_adj` 同理。

#### 数值样例（可直接作为单元测试）

以平安银行 2024-06-13 为锚点：

| date | close | pre_close | ratio | F | close_adj |
| --- | --- | --- | --- | --- | --- |
| 2024-06-13 | 10.800000 | — | — (anchor) | 1.000000 | 10.800000 |
| 2024-06-14 | 10.190000 | 10.080000 | 1.071429 | 1.071429 | 10.917857 |
| 2024-06-17 | 10.150000 | 10.190000 | 1.000000 | 1.071429 | 10.875000 |

校验点：`close_adj(06-14) / close_adj(06-13) − 1 = +1.0913%`，与除权后真实涨跌一致；
若 off-by-one（把 ratio 归到 t−1），`F(06-13)` 会变成 1.071429，
`close_adj(06-13)` 变成 11.571429，在锚点日凭空制造 7.1% 的跳空。

#### 存储精度

**复权价按 double 存储，不得取整到 2 位小数。** 复权价是连续实数，
取整后相邻日比值不再等于真实收益，会直接毁掉复权的意义。

### 6.4 时点正确性

前复权价是未来信息的函数——T 日的前复权价由 T 之后的除权事件反算而来，
其数值本身嵌入未来信息，「仅保留 `date <= T` 的行」这类日期截断**无法**消除它。

本设计的逐股定点复权以该股首个交易日为锚点向后累乘，**不依赖未来事件**，
因此不存在此问题，也不会因回测区间变化而重算。

### 6.5 价格列职责分工与逆变换契约

| 列 | 含义 | 用途 |
| --- | --- | --- |
| `close` 等 OHLC | 不复权真实盘口价（保持现状语义） | 涨跌停判定、价格阈值、整数关口、成交额、对外展示的可执行价 |
| `adj_convention` | 该行的复权口径（`raw`/`qfq`/`unknown`） | 复权体系只消费 `raw` 行，见 7.1 |
| `adj_ratio` | 单事件除权比例（事实层） | — |
| `stock_daily_adj.adj_factor_fixed` | 逐股定点累计因子（视图层） | 逆变换的除数，见下 |
| `stock_daily_adj.close_adj` 等 | 定点复权价 | 均线、动量、比率类因子、收益率、**形态识别** |

#### 三类而非两类

v4 写作「比率型用复权价、绝对价型用不复权价」，这是**假二分**，无法执行。
`resistance_zone_detector`、`low_123_trendline_detector`、
`bottom_divergence_breakout_detector`、`shrink_pullback_detector` 等
**必须在复权序列上做形态识别**（否则除权假断层正是 6.7 要消除的问题），
而它们的输出本身就是绝对价位（阻力位、止损价、买点价）。
这类量既不能用不复权价计算，其输出也不能直接当作可执行价。

正确的分类是三类：

| 类别 | 计算空间 | 输出处理 | 例子 |
| --- | --- | --- | --- |
| 比率型 | 复权 | 直接用 | 均线比、动量、突破比、收益率 |
| 纯绝对价判定 | 不复权 | 直接用 | 涨跌停、整数关口、成交额 |
| **形态派生价位** | **复权** | **必须逆变换回真实价** | 止损价、买点价、阻力位、趋势线价位 |

#### 逆变换公式与锚点选择

```text
real_price = adj_price / adj_factor_fixed(decision_date)
```

**除数取决策日的因子，不是价位来源日的因子。** 这一点最容易写错，且错了会静默产出
不可执行的挂单价：若某摆动低点位于 60 个交易日前、其间发生过除权，
用来源日因子换算得到的是除权前的名义价，与当前盘口不在同一尺度。
取决策日因子则得到「该结构位在今天等价于多少钱」，正是下单需要的数值。

推论：**任何跨越除权日的形态派生价位都必须重述**，不得直接引用历史名义价。
这恰是 v4 规则在最要紧场景（跨除权的止损位）产出错误答案的地方。

#### 实现约束

逆变换**必须封装为单一共享函数**，在 detector 输出边界统一调用。
6.7 列出的 11 个模块若各自实现，必然出现锚点日选择不一致。
实施计划须指定该函数的位置与签名，并在两个范例 detector 中给出完整调用示范。

### 6.6 复权约定的显式声明

价格连续性复权对**配股**隐含「投资者全额参与配股并注入现金」的假设。
例：10 配 3、配股价 5 元、前收 10 元，除权参考价 `(10 + 0.3×5)/1.3 = 8.846`，
ratio ≈ 1.130，复权序列显示当日收益 0——但这只对行权者成立，
不参与配股者实际按 8.85 计价并承受摊薄。回测直接用 `close_adj` 算收益会高估被动持有收益。

**本设计的复权约定为「假定全额参与配股、现金股息立即再投资且不计税」。**

#### v7 定稿：不能只打标，必须给出处置（P0-6）

v6 写「由回测侧决定是否覆盖处理」，而回测设计从未接手——**这条现金流至今没有归宿**。
后果是 `close_adj` 的收益序列隐含了一笔**未出资的资金注入**：
复权价假设投资者按配股价缴款，但组合里并没有这笔钱。用它算收益必然高估。

本项目的定位是**信号有效性研究，不是组合收益模拟**（回测设计 2 节），
因此不引入组合层现金账户。定稿处置：

**持有期内发生配股的样本，从收益统计中排除并单独报告排除率。**

理由与边界：

- 排除而非建模，是因为建模需要组合现金账户，而那与「不做组合模拟」的定位冲突，
  为一个稀有事件引入整套账户体系不成比例。
- 排除而非「按除权参考价平仓」，是因为平仓会把配股造成的机械性价格下移
  记为一笔真实亏损——那对不参与配股者成立，对参与者不成立，
  而我们并不知道假想持有者属于哪一类。排除是唯一不需要假设的处置。
- **发生率必须实测而非假设。** 阶段 E 从 `corporate_actions` 统计
  2018–2026 各年的配股事件数与影响样本占比，写入文档。

#### v8 修正：处置方式由「整条剔除」改为「因果性平仓」

v7 定稿为整条剔除，实测审计指出该方案**需要追溯重算此前组合**——
该持仓在配股公告前的每一天都已贡献过组合收益，事后剔除等于回头改历史，
且使组合成分依赖未来事件、序列不可持有。

**改为由回测侧在除权日前一交易日按收盘价强制平仓**（回测设计 7.5）。
配股方案在除权日前已公告，该操作在现实中可执行；
在除权发生前退出，本节的资金注入问题自然消失，无需现金账户也无需两遍计算。

`corporate_actions` 的 `rights_ratio` 与 `rights_price` 因此成为**回测侧的必需输入**，
须保证其召回率——漏标一个配股事件就等于漏了一次平仓。

### 6.6b 公司行为模型（v6 补齐）

v5 的 `adj_event_type` 是**单值枚举**，无法表达真实的公司行为结构。三处缺口：

#### v8 修正：公司行为必须是独立的版本化数据产物，不是主表上的几个列

v6/v7 把公司行为表达为 `stock_daily` 上的 `adj_event_type` 与 `adj_event_detail_json` 列。
实测审计要求把它建成**正式的版本化数据产物**，理由成立且有三条：

1. **回测需要 pin 版本。** 配股剔除、事件分类的召回率会随信源补充而变化，
   而回测结论必须能对应到一个确定的公司行为版本。挂在主表列上无法版本化——
   主表被日常同步持续写入。
2. **召回率是可演进的。** 首版由 `pre_close` 反推，购得积分后由 `dividend` 校正，
   未来可能接入更多信源。每次改进都应产生一个新版本而非原地覆盖，
   否则历史回测结论不可复现。
3. **消费方不止复权。** 回测的配股处置（回测设计 7.5）、事件分类、
   验收 #7 的四类样本抽取都要读它，作为独立产物比散落在主表列上更清晰。

**新增表 `corporate_actions`**（7.6f），主表保留 `adj_ratio` 与 `adj_ratio_status`
这两个**逐日事实**，但事件的**语义解释**移出主表。

#### 缺口一：同日复合事件（最常见，且 v5 完全无法表达）

A 股年度分红方案的标准形态就是复合的——「10 派 3 元转增 4 股」同日除权除息，
`ratio` 是派息与转增两个效应的乘积。单值枚举只能填一个，另一个静默丢失。
这不是边缘情况，而是**分红季的默认形态**。

处置：`corporate_actions.event_types` 为**多值**（分隔符拼接或位掩码，实施计划定），
各分量落在独立列（`cash_dividend_per_share`、`bonus_ratio`、`transfer_ratio`、
`rights_ratio`、`rights_price`，见 7.6f）。
验收 #7 的四类事件样本须包含至少一个复合样本。

#### 缺口二：方向性偏差的论述只覆盖了 `ratio > 1`

6.2 称「现金分红总使 ratio > 1，取整系统性低估累计因子」，
该论述对**缩股**不成立——缩股使 `ratio < 1`，取整偏差方向相反。
误差预算（11 节 #8）须按方向分别累计，不能简单线性相加。

隔离阈值 `|ln ratio| > ln 3` 本身是对称的，不受影响。

#### 缺口三：改变股本但不除权的事件

定向增发、股份回购注销、限售解禁会改变 `total_share`，但**不产生除权**
（增发按市价发行，不调整历史价格）。因此：

- **不得用 `total_share` 的变化去交叉验证 `ratio`**，否则定增日会被误判为漏检的除权事件。
- 反向也成立：送股转增同时改变股本与价格，二者必须一致；
  而派息只改价格不改股本。这个「股本是否同步变化」恰好可用于**区分事件类型**，
  是 `corporate_actions.event_types` 分类的一个免费判据。

| 事件 | 改变价格（产生 ratio） | 改变股本 |
| --- | --- | --- |
| 现金分红 | 是 | 否 |
| 送股 / 转增 | 是 | 是 |
| 配股 | 是 | 是 |
| 缩股 | 是（ratio < 1） | 是 |
| 定向增发 | **否** | 是 |
| 回购注销 | **否** | 是 |
| 限售解禁 | 否 | 否（改流通股本） |

### 6.7 生产因子失真的修复

因子链路改用复权价计算均线、动量、突破比等；涨跌停判定与价格阈值继续用不复权价。

改动面（据代码探查）：`src/services/factor_service.py` 的因子构建主入口，
以及 `src/indicators/` 下的 `ma_breakout_detector`、`divergence_detector`、
`trendline_detector`、`pattern_detector`、`low_123_trendline_detector`、
`bottom_divergence_breakout_detector`、`causal_bottom_divergence_detector`（含 support/events）、
`resistance_zone_detector`、`shrink_pullback_detector`、`gap_detector`、
`multi_timeframe_analyzer`。

实施计划须给出**至少两个 detector 的完整拆分范例**（建议 `gap_detector` 与
`resistance_zone_detector`），否则 11 个模块会各自解释 6.5 的规则。
其中 `gap_detector` 属必须切换项——跳空检测的本质就是区分「除权造成的价格断层」与「真实跳空」。

`stock_daily` 现存的 `ma5`/`ma10`/`ma20`/`volume_ratio` 冗余技术列是不复权口径。
**处置定稿：标记 deprecated 并停止写入，因子一律实时计算**，避免与复权列混淆。

此项改变生产选股结果，属用户可见行为变化，须按 `AGENTS.md` 第 7 节评估并同步
`README.md` 与 `docs/CHANGELOG.md`。

ma5, ma10, ma20, volume_ratio, data_source, adj_factor, adj_anchor_date,

#### `adj_convention`：跨源口径混存的显式化

1.1 的分源实测显示库内复权口径**按数据源混存**：Tushare 为不复权（断裂率 0.29%/0.35%，
与理论值 0.38% 吻合），Efinance 疑似前复权（0.027%，低一个数量级）。
日常同步的 fallback 链会继续引入这种混存。

强行统一口径会牺牲可用性——某源不可用时宁可有 `qfq` 行也好过缺行。
因此改为**如实标记而非强制统一**：

- 各 fetcher 落库时如实写入 `adj_convention`，不确定则写 `unknown`。
- **复权体系只消费 `raw` 行**；`qfq`/`unknown` 行使该点进入 `unverifiable`，
  由 6.2 的逐区间切分自然处理，不额外发明机制。
- 这样既不丢数据，也不让口径污染沿递推链扩散。

**`adj_factor` 保留原值并标记 deprecated，不做原地语义变更。**
`AGENTS.md` 第 7 节要求「优先追加字段、保留旧字段或提供兼容层，避免无提示破坏现有客户端」。
原地改写 260 万行语义会让现有读取方静默拿到不同含义的数据。

### 7.4 新增表 `stock_daily_basic`

存放 `daily_basic` 的市值与估值指标，按 `(code, date)` 关联。独立成表而非加列，
因该数据依赖付费积分、可能整体缺失。

#### 单位：Tushare 原生口径为「万」，落库必须换算（v6 修正）

**v5 此处标注错误，与 1.2 刚修完的成交量事故属同一类。** Tushare `daily_basic` 原生单位
（官方文档核实于 2026-08-11）：

| 字段 | Tushare 原生单位 | 落库单位 |
| --- | --- | --- |
| `total_mv`、`circ_mv` | **万元** | 元 |
| `total_share`、`float_share`、`free_share` | **万股** | 股 |
| `turnover_rate`、`turnover_rate_f`、`dv_ratio`、`dv_ttm` | % | % |
| `pe`、`pe_ttm`、`pb`、`ps_ttm`、`volume_ratio` | 无量纲 | 无量纲 |

v5 写作「`total_mv`（元）、`total_share`（股）」，与原生差 10000 倍。
落库口径统一为**元与股**，与 `stock_daily.amount`（元）、`volume`（股）一致，
换算函数放在 `data_provider/base.py`，与 `lots_to_shares`、`thousand_yuan_to_yuan` 并列。

**这个错误尤其危险，因为验收 #3 检不出它**：`close`(元) × `total_share`(万股) = 万元
= `total_mv`(万元)，两边同为万单位，交叉校验**恒通过**。
若不换算直接落库，下游按「元」消费市值会全部小 10000 倍，
市值分位分组与风格中性对照组随之全错，且没有任何闸门会报警。
故验收 #3 须明确要求**在换算之后**做量级校验，并另加一条绝对量级断言
（如全市场总市值中位数应在 10⁹–10¹⁰ 元量级）。

#### 实测：`circ_mv` 当前非空但恒为 0（v8 补充）

审计在 100 股因子快照上实测到 **`circ_mv` 非空但值恒为 0**，
且真实换手率尚未接入。这比 7.4 原本担心的「单位错误」更基础——
该字段目前根本没有数据，只是占了个位。

两条后果：

1. 任何以 `circ_mv` 为输入的现有逻辑（若有）实际是在用 0 运算，
   须在阶段 A 排查其消费方，确认是否已在静默降级。
2. **验收 #30/#31 必须包含「非零率」检查**，而不只是单位与量级检查。
   一个恒为 0 的列能通过任何比例型校验。

真实换手率的接入归属本项目阶段 H（`daily_basic.turnover_rate`），
在此之前所有依赖换手率的判定须显式标注为不可用，不得用 0 代替。

#### `circ_mv` 的口径歧义

Tushare 官方文档对 `circ_mv` 的描述自相矛盾：字段名与中文名为「流通市值」，
但括号内公式写作「收盘价 × **自由流通**股本」。二者在有限售股的个股上差异显著。
落库时须实测判定 `circ_mv / close` 更接近 `float_share` 还是 `free_share`，
把结论写入文档后再定义该列语义，不得沿用文档表述。

字段：`code`、`date`、`total_mv`（元）、`circ_mv`（元，口径待实测）、
`turnover_rate`（%）、`turnover_rate_f`（%）、`volume_ratio`、`pe`、`pe_ttm`、`pb`、
`ps_ttm`、`dv_ratio`（%）、`total_share`（股）、`float_share`（股）、`free_share`（股）、
`limit_status`（0–6）、`data_source`、时间戳。

`limit_status` 为顺带收益：它给出收盘涨跌停状态（含一字板与普通涨停的区分），

## 八、执行阶段与依赖

依赖关系是有向图而非线性序列。

```text
A0 拆除 qfq 引信（硬开关，默认关闭）——最优先，先于一切取数
                                      ↓
A 备份与建表 → B 交易日历 → G1 上市/退市日期（免费，baostock）
                                      ↓
                    C 日线全窗口回补 → 写入 stock_daily_staging（不碰生产表）
                                      ↓
                    D 口径全表校验（在 staging 上，并与生产表逐行比对）
                                      ↓
                    K0 提升前选股差异对比（C2 的准入闸门，见下）
                                      ↓
                    C2 原子提升 staging → stock_daily（K0 通过才执行）
                                      ↓
                    E ratio 计算 + 缺口四态归因（未归因即切断，见 6.2b）
                                      ↓
                              F 累计因子与复权价
                                      ↓
                    H2 双层比对与主口径升级（需积分，见下方说明）
                                      ↓
I K线审计重跑 ←──────────────────────  J 因子链路切换（带开关）
                                      ↓
                              K 切换前后选股差异对比
                                      ↓
                              L 默认值翻转（见 13.2）

G2 ST 与行业状态时间线（需积分，与 C–F 独立，可并行）
```

**关键排期约束：D–F 必须在不依赖积分的前提下独立跑通并产出完整可用的复权体系。**
若把历史段主口径直接写成「读 `adj_factor`」，阶段 D–F 就被积分卡住，
与 9.5「先验证代码再买三天积分」的顺序冲突，且积分到期后无法重跑。
因此免费路径（`pre_close` 重建）始终是可独立交付的完整实现，
积分只用于阶段 H2 的校验与升级——**这也意味着即使不买积分，项目仍可交付，只是少一层证据**。

| 阶段 | 内容 | 积分依赖 |

- A0 必须排在最前。qfq 引信的触发条件是「积分可用」，而积分可能在项目任意时点购入；

- C 与 C2 拆分使「写入」与「提升」解耦。D 的校验对象是 staging 与生产表**两份数据**，
  只有保留原始生产表才能定位 1.1 发现的分源口径边界。
  提升前的快照 `stock_daily_pre_backfill` 提供表级回滚，粒度远优于整库备份。

### 8.0 本期可开工范围（v7 定稿）

评审结论是**分批开工**：数据侧的前段可以动手，后段与确认性回测继续暂缓。

| 阶段 | 状态 | 理由 |
| --- | --- | --- |
| A0 拆 qfq 引信 | **可开工** | 独立、极小、当前休眠，且越早越好（1.8） |
| A 备份与建表 | **可开工** | 纯 schema，无行为变化 |
| B 交易日历 | **可开工** | 新增 fail-closed 接口，不改既有语义 |
| G1 上市/退市日期 | **可开工** | baostock 免费，且是 E 与多项验收的前置 |
| C 回补到 staging | **可开工** | 写 staging，不触碰生产表 |
| D 口径校验 + K0 | 暂缓 | 需 C 产出后才有对象 |
| C2 原子提升 | **暂缓** | 用户可见变更，须先有 K0 证据（8.1） |
| E / E2 / F 复权体系 | **暂缓** | 6.2b 的 `gap_flat` 占比未实测，覆盖率未知 |
| J / K / L 因子切换 | **暂缓** | 依赖 F |
| H / H2 积分窗口 | **暂缓** | 按 9.5，代码跑通后再买 |

**暂缓不等于停止设计**，而是不落生产改动。C 跑完后 `gap_flat` 与配股排除率
两个实测数字才有来源，它们分别决定 E 的覆盖率与回测的样本损失，
是后续阶段能否开工的实证依据。

**确认性回测在 J 完成前不得开工**，理由见回测设计 11 节：
J 之前因子链路仍读不复权价，历史重放会把除权假断层复制到 2018–2026 全窗口。

### 8.1 C2 是用户可见变更，必须有自己的闸门（v6 修正）

**v5 的事实错误**：阶段表与 PR 拆分把 C/C2 标注为「数据层，无行为变化」，
理由是 `ADJ_ENABLED=false`。这不成立——`ADJ_ENABLED` 只控制**因子是否用复权价**，
不控制**因子读到什么数据**。C2 一提升，生产因子的输入立即改变，
而 K（切换前后差异对比）排在 J 之后，等于 C2 造成的行为变化没有任何对比闸门。

影响面比「覆写 561 天存量」更大，有两条独立路径：

1. **覆写路径**：2024–2026 存量被重取数据替换。1.1 已实测该区间存在分源口径差异
   （Efinance 疑似前复权），替换会改变价格序列本身。
2. **新增路径**：2018–2023 是纯新增，看似不影响「当前」选股，但所有**回溯窗口类因子**
   都会变——250 日均线、历史分位数、阻力位与趋势线的回溯基准、
   长周期摆动点识别。这条路径更隐蔽，且无法通过「只看最近 N 天」规避。

#### 为什么不能把 C2 挪到 J 之后

J 让生产因子改读 `stock_daily_adj`，而该表由 F 从 staging 的 `pre_close` 算出。
若此时生产 `stock_daily` 仍是旧数据，生产会同时消费「新复权价」与「旧不复权价」
两套不一致的序列（6.5 的三类分工要求二者并用），比现状更糟。
**C2 必须在 J 之前，因此只能给它配一个自己的闸门。**

#### K0 的内容

在 `ADJ_ENABLED=false` 下，用 staging 与生产表各跑一遍近期选股，比对候选集：

- 差异应集中在 1.1/1.2 已识别的口径异常源与年份上，且可逐条归因。
- **若在口径一致的区间出现大面积候选变化，说明重取数据本身有问题，阻断提升。**
- 报告须分别列出「覆写路径」与「新增路径」的贡献——
  可通过「只提升新增段」与「只提升覆写段」两次对比拆分归因。

#### 分段提升（推荐）

C2 拆成两次提升更利于归因：先提升 2018–2023 纯新增段（K0-a），
再提升 2024–2026 覆写段（K0-b）。两个变量分离后，
任一环节出问题都能立刻定位到是「新增历史」还是「覆写存量」造成的。

## 九、运维与连锁影响

### 9.1 写入路径改造（三条路径，不止回补服务）

**v5 修正：v4 只盯了回补服务，遗漏了日常同步。** 全仓核查确认，
`pre_close` 在**所有**写入路径上均未持久化：

| 路径 | 位置 | 现状 |
| --- | --- | --- |
| 日常增量同步 | `market_data_sync_service.py:349-364` | 列清单为 `(code, date, open, high, low, close, volume, amount, pct_chg, data_source, created_at)`，**无 `pre_close`** |
| 回补服务 | `fast_backfill_service.py:164-203` | 同样丢弃 `pre_close` |
| 回补脚本 | `scripts/fast_backfill.py:116-138` | 同上 |

**这直接击穿 6.0 的双层设计**：增量段的唯一免费方法就是 `pre_close` 重建，
而该字段从未落库。积分一到期，复权体系即断供。

因此 `pre_close` 与 `adj_convention` 的落库改造**必须覆盖全部三条路径**，
其中日常同步路径优先级最高——它决定了系统能否长期自持。

`FastBackfillService` 的其余现状问题：

1. **逐行 `conn.execute` INSERT**（171-201 行）。补至 2018 约 1160 万行
2. **逐行 `conn.execute` INSERT**（171-201 行）。补至 2018 约 1160 万行
   （5580 × 2080），逐行写按 2000–5000 行/秒计需 40 分钟至 1.6 小时；
   改 `executemany` 可降至十分钟内。
3. **限速硬编码**：45 次/分（77-82 行）与 `sleep(1.3)`（91 行）均为字面量，
   持有 5000 积分（500 次/分）时无法提速。
4. **无向后回补入口，且续跑逻辑会跳过存量日期**：`backfill_to_trade_date` 的起点是
   `_get_latest_complete_date() + 1 天`；`_is_date_complete`（132-138）按
   `COUNT(DISTINCT code) >= min_full_count`（默认 3000）判定，而现有 561 天中 560 天的
   股票数超过 4000，**全部会被判为已完成而跳过**。不改造则 `pre_close` 永远为 NULL，
   阶段 D 与目标 3 同时落空。

改造：

- **三条路径统一新增 `pre_close` 与 `adj_convention` 落库**，单位换算复用 1.2 的辅助函数。
- 回补路径写入目标改为 `stock_daily_staging`（阶段 C），生产表由 C2 提升。
- 改批量写入。
- 限速参数化（默认保持现值以兼容免费档）。
- 新增向后区间回补入口。
- **`_is_date_complete` 引入口径版本位**：仅当该日数据已按当前口径版本写入时才算完成，
  使续跑能力保留、跨版本重取不被跳过。

### 9.2 K 线审计的连锁影响

`KlineAuditService`（`kline_audit_service.py:66,86,256`）以 `instrument_master`
（active、非 ST）为期望域，用 `list_date` 过滤「尚未上市」。当前 `list_date` 失真，
审计不会要求 2024 年之前的数据；**修正为真实上市日后，2018–2024 全窗口的停牌日
会被大量标记为缺口**。

处置须把两类检查拆开，不能一并降级：

- **交易日历级缺口**（全市场某日缺失或行数异常）→ **永远阻断**，与个股豁免无关。
- **个股缺行** → 必须可归因（停牌/未上市/已退市/抓取失败）。前三类进豁免；
  **无法归因的一律阻断该股复权物化**，不得塞进 `kline_skip_registry`。
- 豁免规则须有到期时间与复核记录，避免一次批量豁免永久掩盖后续真实故障。
- 审计窗口配置化，按年份分批（5580 股 × 2080 交易日约千万级 `(code, date)` 对）。
- 期望域改用 point-in-time 的 `list_date` + `delist_date`。
- **期望域不再使用 ST 条件**：是否 ST 与「该日是否应有 K 线」无关，
  这个条件本身就是错误的耦合。移除后审计不再依赖 ST 时间线，
  与阶段 G2 完全解耦——即使 G2 因积分未购而缺失，审计仍可独立完成。

### 9.3 稳态增量维护

- 每日任务落库时写入 `pre_close`（同 9.1 改造）。
- 每日按 `F(t) = F(prev) × ratio(t)` 向前延展一天，不重算历史。
- **个股级不可用**（当日 ratio 落入隔离区或 `unverifiable`）：该股当日不产出复权因子、
  不进候选池、写事件告警。**不得猜值，不得静默回退到不复权价。**
- **全市场级不可用**（Tushare 当日整体故障导致全市场跨源）：这属于数据源故障，
  走既有 K 线治理闸门与告警，**不静默停摆也不静默降级**。
  可配置允许 N 日内用最近一次有效 `F` 冻结延展，且**仅对不跨除权日的窗口成立**。
  该项须按 `AGENTS.md` 第 7 节「单一数据源失败不应拖垮主流程」写明取舍理由。
- `FactorService` 遇复权数据不可用时按 `ADJ_STRICT_MODE` 决定报错或跳过该股，
  **不提供「静默回退到不复权」的选项**。

### 9.4 数据库并发

「非交易时段执行」不足以避免冲突。SQLite 单写者模型加约 2080 个按日事务，
与每日任务相撞即 `database is locked`。须明确：

- **启用 WAL**：全库当前**没有任何** `journal_mode` 设置，这是新增项而非确认项。
  须评估 WAL 对 Docker 卷与网络文件系统的兼容性（部分挂载方式下 WAL 不可用）。
- `busy_timeout` 现为 30s（`storage.py:1226`），须复核在批量写入下是否足够。
- 提供**维护模式开关**，回补期间暂停调度器，并定义进入/退出条件。
- 回补按日提交而非单一长事务。

### 9.5 积分购买时点与窗口内拉取清单

Tushare 高积分档为三天时效。**积分只限制 API 调用，不限制数据留存**——
窗口内落库的数据永久可用，这是整个双层口径成立的前提。

风险不在调用量（合计约 4200 次，按 500 次/分钟计不足 10 分钟），而在开发进度。
顺序：先完成代码改造，用免费接口跑通阶段 A–F、G1；验证通过后再购买三天积分，
集中执行阶段 H，剩余时间用于校验与可能的重拉。

#### 窗口内必须拉完的十项

| 项 | 接口 | 调用量 | 动机 | 到期后可否替代 |
| --- | --- | --- | --- | --- |
| 历史市值 | `daily_basic` | ~2080 | 风格中性化对照组 | **否**，无免费替代 |
| 复权因子 | `adj_factor` | ~2080 | 历史段权威口径 | 部分，`pre_close` 重建可延展 |
| 除权事件 | `dividend` | 按股循环 | 验收 #5 权威信源 | 部分，akshare 完整性未知 |
| ST 历史 | `namechange` | ~5600 | 回测时点正确性 | **否** |
| 行业历史 | `index_member_all` | 按分类循环 | 风格中性对照组的行业匹配 | **否** |
| **涨跌停价** | **`stk_limit`** | **~2080** | **历史涨跌停规则时变，无法规则重建（5.8）** | **否** |
| **停复牌** | **`suspend_d`** | **~2080** | **缺口归因权威源（6.2）+ 持有期停牌判定** | **否** |
| 基准指数 | `index_daily` | 6 | L1 市场环境 | 是，akshare |

前七项是购买的真实理由；后三项因窗口内边际成本近乎为零，顺带拉取以增强交叉校验。
合计约 1.4 万次调用，按 500 次/分钟计约 28 分钟。**档位维持 5000 不变**——
新增的 `stk_limit`、`suspend_d` 均为 2000 积分起（核实日期 2026-08-11）。

#### ST 与行业历史化（回测项目提出的新需求）

`is_st` 当前由股票名是否含 "ST" 派生（`universe_service.py:153`），
`industry` 读 `InstrumentMaster` 当前快照，二者均无历史版本，
在历史重放中构成时点污染。两个接口均为 2000 积分起，落在 5000 档内，无需额外购买。

- `namechange` 输出 `name`/`start_date`/`end_date`/`change_reason`，可重建 ST 区间。
- `index_member_all`（申万三级）输出含 `in_date`/`out_date`，
  须同时拉 `is_new='Y'` 与 `is_new='N'` 才能取到历史成分。

**`namechange` 有已知缺陷，必须规避**（Tushare issue #1858，2026-03）：
入参 `start_date`/`end_date` 实际映射到输出的 `ann_date` 而非名称生效区间，
且底层对 `ann_date` 做隐性 NOT NULL 过滤——**一旦携带日期参数，
所有 `ann_date` 为空的合法历史记录会被静默丢弃**，直接引入幸存者偏差。
正确用法是**不传日期参数、按 `ts_code` 循环**，并在验收中校验
「传与不传日期参数拉到的 ST 区间数一致」。

落库目标为新表 `instrument_status_history`（7.6e）。

**注意 ST 历史化并不足以修好涨跌停判定**——时变的是规则本身而非仅股票状态，
详见 5.8。涨跌停必须走 `stk_limit` 查表。

### 9.7 隔离回放的表复制清单（v6 新增）

`isolated_replay_database`（`bottom_divergence_v2_dataset.py:213`）把生产库的一个切片
流式复制到临时 SQLite。其 `:227-235` 的 import 清单即为**全部**被复制的表：

```text
BoardMaster, DailySectorHeat, InstrumentBoardMembership,
InstrumentMaster, ScreeningRun, StockDaily
```

本项目新增的表**一张都不在其中**：`stock_daily_adj`、`stock_daily_basic`、
`index_daily`、`daily_price_limit`、`suspension_history`、
`instrument_status_history`、`trading_calendar`。

后果是隔离回放中复权价、历史市值、指数、涨跌停、停牌、ST/行业历史全部缺失，
而这些恰是回测时点正确性的全部依赖。**必须扩展该函数的复制清单**，
且扩展方式应改为显式配置而非硬编码 import，否则每加一张表都要改这个函数。

由于该函数属回测项目的复用底座，扩展工作归属回测项目，
本项目只负责保证新表结构与切片键（`code`/`date` 或 `trade_date`）可被按需切片。

### 9.6 拆除 qfq 引信（v5 新增）

1.8 描述的 `_apply_qfq_adjustment` 会在积分到位时自动生效，翻转生产写入语义。
处置分两步，**时序不可颠倒**：

#### 第一步（阶段 A0，最优先）：加硬开关，默认关闭

新增配置 `TUSHARE_QFQ_ENABLED`，默认 `false`。为 `false` 时
`_apply_qfq_adjustment` 直接返回原始 DataFrame，不调用 `adj_factor`。

**为什么必须最先做**：该函数的触发条件是「`adj_factor` 可用」，
而积分可能在项目任意时点购入。若依赖「记得先禁用」这种人为约定，
一次疏忽就会在阶段 H 之后重新污染已验收的数据。拆引信必须先于一切取数动作。

同步更新 `.env.example` 与 `README.md`（`AGENTS.md` 第 1 节要求）。

#### 第二步（阶段 L）：永久移除

`ADJ_ENABLED` 翻转为 `true` 的**同一个 PR** 内删除该函数及其配置项。

**时序约束是双向的**：

- 提前删除 → 001229 那类除权假信号继续存在，且失去唯一的缓解手段。
- 滞后删除 → 新复权体系已生效，再叠加 qfq 即双重复权。

因此二者必须原子发生。该函数现有的四个单元测试
（`tests/test_tushare_fetcher_followups.py:98-163`）随之删除或改写为
「开关关闭时不调用 `adj_factor`」的回归测试。

档位 **5000 积分**：5000/10000/15000 三档常规数据频次相同（均 500 次/分钟），
差异仅在分钟数据与特色数据权限，均不在五层选股链路中。
5000 是能满足 `daily_basic`「无总量限制」的最低档。
（档位与时效为外部条款，核实日期 2026-08-11。）

## 十一、验收标准

| # | 项 | 判定方法与门槛 |
| --- | --- | --- |
| 1 | 交易日历完整 | akshare 与 `exchange_calendars` 双源差异条目为 0；与库内行情双向交叉的差异全部可归因 |
| 2 | 日线覆盖 | 分母为「该日在市（由 `list_date`/`delist_date` 计算）− 该日已知停牌」。判定改为**归因率**：入库行数与 Tushare 当日返回行数一致，且在市但缺失的部分 100% 可归因。不使用固定覆盖率百分比门槛，因停牌占比在 2018–2019 可超过 2%，固定门槛会产生大量合法失败 |
| 3 | 单位口径 | **换算为元/股之后**做 `close × total_share` 与 `total_mv` 的量级交叉核对，偏差超 1% 阻断；**另加绝对量级断言**（全市场总市值中位数落在 10⁹–10¹⁰ 元），因换算前两边同为「万」单位、该交叉校验恒通过、检不出 7.4 的单位错误；跨源 `amount/(volume×close)` 中位数须全部落在 [0.95, 1.05]（1.2 修复后实测已满足） |
| 4 | 口径校验（阶段 D） | 按 `(data_source, 年份)` 的 `ratio ≠ 1` 占比与年均分红次数量级一致；1.2 遗留的 397 条带外记录须给出归因结论；异常源/年份清单为空或已隔离 |
| 5 | **信源命中率** | **购得积分时**：以 Tushare `dividend` 为权威信源，`\|ln ratio\| > 0.05` 的事件须 100% 匹配，无「完整性未知」的让步空间。**未购积分时**：退回 akshare，先抽 200 只股票 × 2018–2026 实测四类事件命中率，**把实测数字写入文档后再定门槛**；小额现金分红允许「未匹配但落在合理股息率区间」记为观测项，避免把不可控外部源设成唯一阻断闸门 |

| 8 | **双层口径一致性（本设计最强的正确性证据）** | 历史段重叠区上，逐事件比对 `pre_close` 重建的 `adj_ratio` 与 `adj_factor_tushare(t)/adj_factor_tushare(prev)`。**这直接验证了增量段将长期依赖的重建方法**，而非等上线后才暴露问题。阈值**按价格缩放**：除权日 `\|Δln\| ≤ 3 × 0.005 / min(close(prev), pre_close)`，非除权日 `≤ 1e-6`；另加累计口径校验 `全期累计对数收益差 ≤ 事件数 × 单事件上界`。**不使用固定 1e-4**——`pre_close` 按分取整对 3 元股的单事件误差上界即达 1.7e-3，固定阈值数学上不可达。**也不使用 `close_adj` 与 `pct_chg` 自比对**——按构造该式恒成立，是自证通过的无效校验。未购积分时退回 baostock 复权序列，并要求其独立于 #5 所用信源 |

### 12.1 回滚

**不依赖整库备份恢复**——每日任务持续写库，回补与验证跨若干天，
整库恢复会丢失这期间的生产数据。

| 层面 | 回滚方式 |
| --- | --- |
| 因子链路 | `ADJ_ENABLED=false` 切回不复权口径，立即恢复原行为 |
| 复权视图 | `DROP TABLE stock_daily_adj`，主表不受影响 |
| 主表新增列 | **保留但停用**（SQLite 旧版本无 `DROP COLUMN`）；`adj_factor` 原值从未改写，无需恢复 |
| 其他新增表 | 可直接删除 |
| 指数迁移 | 双写并存 + 读取开关回切；**不做不可逆删除**，观察期通过后才清理 `stock_daily` 中的 `sh000001` |
| 日线回补 | 幂等增量写入，中断不产生半张表，可直接重跑 |

阶段 A 的完整备份仍需保留，用于灾难恢复而非常规回滚。

### 12.2 数据库后端

`get_db_url()`（`config.py:2318-2326`）恒返回 SQLite，无其他后端分支，
且 `storage.py` 存在 `INSERT OR REPLACE`、PRAGMA、SQLite 专用迁移等方言依赖。

体积估算：现状 1.3GB / 295 万行 ≈ 440 B/行。回补至 1160 万行 ≈ 5.1GB；
主表新增 6 列 ≈ 0.4GB；`stock_daily_adj` 约 1160 万行 × 约 60 B ≈ 0.7GB；
`stock_daily_basic` 约 1160 万行 × 约 300 B ≈ 3.5GB。合计约 9.7GB 加索引。
SQLite 承载范围内，**本期不迁移数据库后端**。真正的瓶颈是写入方式而非容量，
已由 9.1 的批量写入改造解决。

`TUSHARE_QFQ_ENABLED` 是 v5 唯一一个**默认值即为终态**的开关——
它不会像 `ADJ_ENABLED` 那样在阶段 L 翻转为 `true`，而是连同函数一并删除。
之所以仍设为配置项而非直接删函数，是因为阶段 A0 时新复权体系尚未就绪，

#### `ADJ_ENABLED × ADJ_STRICT_MODE` 状态矩阵

| `ADJ_ENABLED` | `ADJ_STRICT_MODE` | 行为 |
| --- | --- | --- |
| false | 任意 | 因子用不复权价，与当前生产完全一致；`ADJ_STRICT_MODE` 无效 |
| true | true | 因子用复权价；该股该日复权不可用则不出信号并告警 |
| true | false | 因子用复权价；复权不可用的个股当日**跳过**（不进候选池）但不告警升级。**不存在「回退到不复权价」的组合** |

`ADJ_ENABLED` 默认 `false` 是灰度期取值，不是终态。目标 3 是**缺陷修复**而非能力增强，
默认不生效等于目标不交付。因此明确翻转条件：

### 13.4 PR 拆分建议

本项目一次性包含日线回补、复权体系、交易日历扩展、审计调整、11 个 detector 切换、
指数迁移，范围偏大。按 `AGENTS.md` 第 9 节「用户可见变更优先通过 PR 合入」，
建议按阶段边界拆分为可独立回滚的 PR：

1. **`A0 拆除 qfq 引信`**（最先合入，独立且极小，无行为变化——该函数当前休眠）
2. `A + 9.1 三路径写入改造 + 13.1 配置映射`（含 `pre_close`/`adj_convention` 落库，无行为变化）
3. `B 交易日历扩展`（新增 fail-closed 接口，不改既有语义）
4. `G1 + C 回补到 staging`（数据层，**不触碰生产表**，真正无行为变化）
5. `D 口径校验 + K0 差异对比`（只出报告，不改数据）
6. **`C2 原子提升`**（**用户可见变更**，K0 为准入，验收 #20/#21/#29；建议按 8.1 分两次提升）
7. `E + F 复权体系`（数据层，`ADJ_ENABLED=false` 时无行为变化）
8. `I 审计调整`
9. `J + K 因子切换 + 6.5 逆变换函数`（用户可见，需差异对比证据）
10. `L 默认值翻转 + 永久移除 _apply_qfq_adjustment`（原子）
11. `H 积分窗口十项拉取`（独立，可并行）
12. `E2 缺口归因升级`（依赖 H）
13. `H2 双层比对与主口径升级`（依赖 F 与 H；未购积分时整个 PR 跳过，不影响其余交付）

第 4、5、6 项必须是**三个 PR**。合成任意两个都会让 staging 的隔离价值消失——
4+5 合并意味着校验与写入同批，5+6 合并意味着闸门与提升同批。

**v6 修正**：v5 把第 4–6 项统称「数据层，无行为变化」，这是事实错误。
C2 提升即改变生产因子输入，理由见 8.1。
