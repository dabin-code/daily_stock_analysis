## 一、背景：为什么「至今无法回测任何一条选股结果」

### 1.1 根因链条

```text
factor_service.build_factor_snapshot 从不写入 has_stop_loss
        ↓
five_layer_pipeline.py:570  fs.get("has_stop_loss", False) 恒为 False
        ↓
trade_stage_judge.py:62  if not has_stop_loss: return TradeStage.FOCUS
        ↓
所有候选停在 focus/watch，trade_plan_builder 不产出交易计划
        ↓
回测的 entry 信号族样本恒为空 → 无任何可评估的买入信号
```

### 1.2 实测证据（2026-08-11 全库查询）

| 观测项 | 实测值 | 含义 |
| --- | --- | --- |
| `screening_candidates` 总数 | **652** | 全部快照可回测样本 |
| `trade_stage` 分布 | focus 644 / watch 8 | **probe_entry、add_on_strength 均为 0** |
| 带 `trade_plan_json` 的候选 | **0** | 无一条产出交易计划 |
| `factor_snapshot_json` 含 `has_stop_loss` 键 | **0 / 652** | 直接证实该字段从未写入 |
| `screening_runs` 跨度 | 94 天，2026-03-13 → 2026-08-10 | 生产运行仅 5 个月 |
| 已有回测运行 / 评估样本 | 27 次 / evaluated 762 | 跑得动，但全是观察族 |

`setup_type` 分布：`trend_breakout` 312、`low123_breakout` 273、
`bottom_divergence_breakout` 39、`gap_breakout` 16、`trend_pullback` 4。

`five_layer_pipeline.py:563-571` 存在双路径：`BOTTOM_DIVERGENCE_LAYERED_ENTRY`
走正常逻辑，其余 setup 走失效分支。实测 652 条候选**无一条**属于前者，故 100% 落入失效分支。
单元测试全绿是因为 fixture 显式写了 `has_stop_loss: True`（12 处）。

### 1.3 样本量约束与既有解法

快照重放的样本上限等于生产运行天数（当前 94 天、652 条），不足以做统计推断。
解法是在历史交易日上重跑管线——**而这套引擎仓库里已经存在**，见第三节。

---

### 1.4 实测审计结论（2026-08-11）与结论覆盖面

实际运行给出的关键数字：

| 观测 | 结果 |
| --- | --- |
| 核心测试 | 277 项全部通过 |
| 完整离线测试 | 3073 passed、**6 failed**，其中 5 项涉及黄金候选 / L2 板块热度 / 主题上限 |
| 止损修复路径 | 001337 / 2026-08-05 当前停在 `focus`；模拟修复后变为 `probe_entry`，产出 entry=43.27、stop=30.7296 的完整计划 |
| 除权失真量级 | 000001 / 2024-06-14 原价 −5.7407% vs 实际经济收益 +0.9921%；raw MA20 偏差 **6.7939%** |
| 隔离重放 | 百股重放**全部 fail-closed**，因指数历史不足 |
| 算力 | 500 股单日因子 14.822 秒，串行外推全期约 **82.4 小时** |

止损修复那条最重要：它把 5.1 的根因假设从推断变成了**已验证的可行路径**——
改完确实能产出 entry 族候选与完整交易计划，不是纸面推演。

#### 结论覆盖面的硬边界

即使全部阻断闭合，本项目能给出的**严格历史结论也只覆盖「L2 关闭」下的策略**，
即 L1/L3/L4/L5 四层。原因见 6.4：主题与概念成分只有最新快照，无法 as-of 化，
这是数据源层面的缺失，不是实现问题。

**完整 L2 的验证只能依靠两条替代路径**：生产运行期的短期快照重放（样本量小），
以及设定冻结后的前瞻跟踪（需要时间）。二者都无法在本项目内完成。

这条边界必须写在报告首页而非附注——「五层策略有效」与
「五层中的四层在 L2 关闭时有效」是两个不同的结论。

## 二、目标与非目标

### 2.1 目标

1. 回答「五层选股策略的信号是否有效」，而非「模拟组合能赚多少钱」。
2. 样本量足以支撑统计推断，且诚实披露有效样本量。
3. 可复现、可对比。
4. 可归因到层、形态、市场环境。
5. 时点正确。

### 2.2 非目标

- 不做撮合级组合模拟（仓位管理、资金曲线、手续费优化）。
- 不做参数寻优。本设计产出证据，不是自动调参器。
- 不追求「跑赢大盘」的绝对收益断言。
- 不新建重放引擎、缓存层、检查点机制（见第三节）。

1. **候选落库与隔离**：现有重放产出 `ValidationSample`（服务于策略验证），不落候选表。

2. **ST / 行业的历史版本化**：当前是时点污染源，见 5.3。
3. **策略无关的编排入口**：现有 CLI 与依赖组装深度绑定底背离 v1/v2

除此之外不新建任何基础设施。

## 四、两种重放范式

| 维度 | 快照重放（现有，保留） | 历史重放（复用既有引擎） |
| --- | --- | --- |
| 候选来源 | 已落库 `screening_candidates` | 历史交易日重跑五层管线 |
| 回答的问题 | 实际做过的决策，结果如何 | 策略本身在历史上是否有效 |
| 样本量 | 受限于生产运行天数（当前 652） | 受限于数据跨度 |
| 用途 | 生产决策的事后审计 | 信号有效性研究、消融、校准 |

两者写入同一套 `five_layer_backtest_*` 表，run 级以 `replay_mode` 区分。
**聚合与报告按 `replay_mode` 严格隔离，不得混合统计**——样本生成机制不同，混算无意义。

## 五、前置修复（阶段 0）

### 5.1 `has_stop_loss`：改为 setup 级统一解析

**v3 的方案（对齐 `_has_stop_loss_anchor`）不可行**：该函数读 `trade_plan`，
而管线 `:572` 先判交易阶段、`:588` 才建交易计划——判阶段时计划尚不存在，构成循环依赖。
回测侧能用是因为它读的是已落库候选。

**正确方案**：setup 级止损解析逻辑**已经存在**，只是位置错了。
`trade_plan_builder.py:268-319` 已按 setup 分支解析：

| setup | 止损来源 |
| --- | --- |
| `BOTTOM_DIVERGENCE_LAYERED_ENTRY` | `resolve_current_stage_stop_loss(fs)` |
| `low123_breakout` | `fs["pattern_123_stop_loss"]` |
| `bottom_divergence_breakout` | `fs["bottom_divergence_stop_loss"]` / `exit_plan.initial_stop_loss` |
| 缩量回踩 | `fs["shrink_pullback_stop_loss_price"]` |
| 其余 | `risk_params["stop_loss"]` 兜底 |

修复方式：抽出共享函数

```python
def resolve_stop_loss_for_setup(
    setup_type: SetupType,
    factor_snapshot: Mapping[str, Any],
    risk_params: Mapping[str, Any],
) -> Optional[float]:
    ...
```

L5 与 `trade_plan_builder` **共用同一实现**，L5 的 `has_stop_loss` 由
`resolve_stop_loss_for_setup(...) is not None` 派生。

- **不写布尔进因子快照**：布尔丢失止损价，且必然与计划构建器漂移。
- **回归风险**：大量候选将从 `focus` 升级为 entry 族，属用户可见行为变化
  （推送内容、报告结构、通知量）。须带开关灰度并做切换前后分布对比。

### 5.2 `rule_score` 被覆盖

`five_layer_pipeline.py:664`：

```python
c.rule_score = stage_p + pool_p + theme_p + c.rule_score * 0.01
```

原始分被压缩 100 倍作排序尾数，落库的 `rule_score` 实为层级优先级。
回测拿它做 Rank IC 会度量层级映射而非因子质量。

修复：新增 `raw_rule_score`（原始）与 `priority_score`（重排后），
`rule_score` 保持现值以兼容既有消费方（`screening_notification_service.py:444`、
`storage.py:3289`）。只增不改。

### 5.3 run 级复现字段未写入

`market_data_version`、`theme_mapping_version`、`candidate_snapshot_version`、
`rules_version` 四字段定义了却从无赋值，直接违背「多次运行可对比」的需求。

- 全部落实写入，取值复用 3.1 的既有指纹机制，不新造哈希方案。
- `rules_version` 取影响选股的配置项子集哈希，**不取 git commit**——
  后者会因无关改动而变化，导致本可对比的运行被误判为不可比。

### 5.4 指标口径混合缺陷

`group_summary_aggregator.py:272-356` 把 entry 族的 `forward_return_5d` 与
observation 族的 `risk_avoided_pct`（构造上非负）混入同一 `win_rate`/`profit_factor`，
系统性抬高评级。

修复：顶层 `win_rate`/`profit_factor` 只对 entry 族计算，observation 族单列。
混合口径列标 deprecated 并停止写入。

### 6.1 现状盘点

| 输入 | 时点状态 | 处置 |
| --- | --- | --- |
| 日线行情 | 已 as-of（`factor_service.py:121`） | 复用；改用 `close_adj`（6.5） |
| 因子快照 | 已 as-of（`build_factor_snapshot(trade_date=)`） | 复用 |
| 市场环境 | 重放侧已 PIT 化 | 复用 `replay.py:870-926` 范式 |
| 板块热度 | 按 `trade_date` 存，有历史 | 见 6.2 隔离问题 |
| 股票宇宙 | `list_date`/`delist_date` 可算 | 依赖数据基础设施 G1 |
| **ST 状态** | **当前股票名派生，无历史** | **泄漏，见 6.3** |

| **主题/概念成分** | **仅最新快照** | **泄漏，见 6.4** |

### 6.2 板块热度：重放会覆写生产表

`daily_sector_heat` 唯一键为 `(trade_date, board_name)`（`storage.py:1122`），
**无 `run_id`/`scope` 列**，写入为先删后插（`storage.py:3689-3696`）。
历史重放若计算板块热度，会直接覆写生产数据。

v3 写的「写回测专属命名空间」是不存在的机制，此处更正。两个可选方案：

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **A. 复用 `isolated_replay_database`** | 零 schema 改动，已验证 | 每次重放全量拷贝库，磁盘与耗时成本高 |
| B. 给 `daily_sector_heat` 加 `scope` 列 | 无拷贝开销 | 改动生产表，需迁移与唯一约束调整 |

**默认取 A**，与「不新增平行实现」一致；若实测拷贝成本不可接受再评估 B，
并在实施计划中给出成本实测数字作为决策依据。

### 6.2b 隔离回放的复制清单必须扩展（v5 新增阻断）

选定方案 A 之后随之而来的问题：`isolated_replay_database`
（`bottom_divergence_v2_dataset.py:213`）复制哪些表，是由 `:227-235` 的 import
清单**硬编码**的，当前只有六张：

```text
BoardMaster, DailySectorHeat, InstrumentBoardMembership,
InstrumentMaster, ScreeningRun, StockDaily
```

本设计与数据基础设施新增的表**一张都不在其中**：`stock_daily_adj`（复权价）、
`stock_daily_basic`（历史市值）、`index_daily`（基准指数）、
`daily_price_limit`（涨跌停）、`suspension_history`（停牌）、
`instrument_status_history`（ST/行业）、`trading_calendar`、
以及本设计的 `backtest_replay_candidates`。

后果是隔离回放中时点正确性的**全部依赖同时缺失**，且多数会静默降级
（读不到表 → 字段为空 → 走 fallback 分支）而非报错。

处置：

- 扩展复制清单，并把它从硬编码 import 改为**显式的表与切片键配置**，
  否则每新增一张表都要改这个函数，且遗漏不会被发现。
- 各表的切片键不同（`(code, date)` / `(trade_date, ...)` / 全量小表），
  配置须支持按键类型选择切片策略；`instrument_status_history` 与
  `trading_calendar` 体量小，直接全量复制。
- 加一条**启动自检**：隔离库建立后校验清单内每张表非空（或显式声明可空），
  缺表即报错退出，不允许静默降级。

### 6.2c 市场环境仍读旧指数表（v5 新增阻断）

`bottom_divergence_v2_dataset.py:240` 把 `market_guard_index` 直接并入 `stock_codes`
从 `StockDaily` 复制，`bottom_divergence_v2_replay.py:874-878` 用
`repository.get_range(index_code, ...)` 从同一张表读——
即**指数被当作一个普通股票 code 存在 `stock_daily` 里**，
默认值 `sh000001`（`config.py:699`）。

该 code 在库内**仅 464 行**，连 2024–2026 的 561 个交易日都缺 97 天，
更不覆盖 2018–2023。因此历史重放跑保留期时 L1 市场环境完全无数据。

**这是硬阻断，不是精度问题**：不切换读取源，本项目的保留期验证无法进行。

处置：重放路径改读数据基础设施的 `index_daily` 表（其 5.6 已列为必做）。
切换须同时覆盖生产实时路径（`screening_task_service.py:373-375` 走
`fetcher_manager` 实时取数）与重放路径（读库）——两条路径本就不同源，
不对齐则「重放结果」与「实际决策」不可比，消融与对照的结论都会落空。

### 6.3 ST 与行业：新增历史化，纳入积分窗口

`is_st` 由当前股票名是否含 "ST" 派生（`universe_service.py:153`），
`industry` 读 `InstrumentMaster` 当前快照。二者均无历史版本。

**污染面比策略侧更广**：7.2 的风格中性对照组用行业匹配构建，
因此泄漏同时污染策略侧与基准侧，主指标「策略 − 对照」两端同时失真，偏差方向不确定。

数据源已核实，**均在 5000 积分档内，无需额外购买**：

| 项 | 接口 | 积分 | 输出 |
| --- | --- | --- | --- |
| ST 历史 | `namechange` | 2000 起 | `name`/`start_date`/`end_date`/`change_reason` |
| 行业历史 | `index_member_all`（申万三级） | 2000 | 含 `in_date`/`out_date` |

**`namechange` 有已知缺陷，必须规避**（Tushare issue #1858，2026-03）：
入参 `start_date`/`end_date` 实际映射到输出的 `ann_date`，而非名称生效区间；
且底层对 `ann_date` 做隐性 NOT NULL 过滤，**一旦携带日期参数，
所有 `ann_date` 为空的合法历史记录会被静默丢弃**。

- 正确用法：**不使用日期参数**，按 `ts_code` 循环拉取（约 5600 次调用，
  500 次/分钟下约 11 分钟）。
- 验收须校验：拉取到的 ST 区间数不随是否传日期参数而变化。

`index_member_all` 须同时拉 `is_new='Y'` 与 `is_new='N'` 才能拿到历史成分。

上述两项**追加进数据基础设施 9.5 的积分窗口清单**（由六项扩为八项）。

### 6.4 主题/概念成分：不可消除的偏差

概念板块成分是时变的，历史版本无可得数据源（申万行业可历史化，概念板块不行）。
用今天的成分表回放 2018 年，等于让策略预知某股日后会被归入热门概念。

处置：不掩盖，显式量化。

1. L2 主题层在历史重放中默认**关闭**，作为消融实验的一个开关项。
2. 主报告以「L2 关闭」为基准结论；「L2 开启」结果单独报告，
   标注为**乐观偏差上界**而非有效性证据。
3. 二者差值即主题层的疑似前视收益，本身是有价值的诊断量。

**这意味着历史重放无法完整验证五层中的 L2**，只能严格验证 L1/L3/L4/L5。
必须写入最终报告的局限性章节。

### 6.5 复权口径

收益计算全部使用数据基础设施产出的 `stock_daily_adj.close_adj`（逐股定点复权）。

- 锚点为逐股首个有效交易日，与回测区间解耦。
- **不可用区间拒绝出信号**：遇复权不可用区间跳过该股该区间，计入
  `suppression_reason`，**不得静默回退到不复权价**。
- 快照重放模式的历史候选存在已知隐患：冻结的 `trade_plan.entry_price` 是决策时原始价尺度，
  前向 bar 若来自不同复权锚点会尺度错配。该模式样本须标记 `adj_scale_unverified`，
  不参与跨期聚合。

### 6.6 泄漏探针

在重放引擎中注入一个「未来 5 日收益」因子作为**负控制**：
时点正确时该因子在正常路径下应无法被访问；若能访问并产生异常高 IC，说明存在泄漏通道。
比逐行代码审查更可靠，作为回归测试长期保留。

## 七、成交与生命周期规则

v3 完全未定义，此处补齐。原则是复用既有执行模型
（`execution/execution_model_resolver.py`）的成交时点与顺延逻辑，
但**涨跌停阈值改为查表**（7.2）、**停牌判定改为读权威表**（7.3）——
这两处既有实现的口径对历史回测不成立。

### 7.1 T+1

信号在交易日 T 收盘后产生，A 股 T+1 制度下最早于 T+1 开盘可买入。

- **入场价**：T+1 开盘价（conservative 模型现行口径，`execution_model_resolver.py:107`）。
- **持有期起点**：T+1。k 日前向收益覆盖 T+1 至 T+k，**不含信号日 T 当日涨跌**。
- 这一条必须在指标定义中写死。若把 T 日收益计入，等于假设收盘瞬间成交，会显著高估。

### 7.2 涨跌停

- **入场受阻**：T+1 一字涨停或开盘即涨停无法买入，标记 `limit_blocked`，
  该样本不计入 entry 族收益统计，但**必须计数并单独报告占比**。
- 剔除 `limit_blocked` 会系统性移除最强信号，对策略是**保守方向**的偏差；
  但占比过高会使结论失真，因此设阈值：占比超过约定上限时该分组结论标为不可靠。
- **出场受阻**：跌停当日无法卖出，顺延至下一可成交日。
  **成交价必须是下一可交易日的开盘价**，与 8.2c 的出场约定一致；
  顺延期间该持仓仍在 `H(d,k)` 内并按延续日公式计收益，
  即**跌停当日的亏损必须被实现，不得跳过**。v6 只写了「顺延」未写价格，
  实施时极易误用「顺延日收盘价」或直接跳过受阻日，两者都会系统性低估下行风险。

#### 涨跌停必须查表，不能靠规则重建

v3 计划复用 `limit_pct_resolver` 的分板阈值并配合历史 ST 状态。**这不成立**——
时变的是规则本身，不只是股票状态。该模块的注释已自陈缺陷：

> 创业板 only moved to ±20 % on 2020-08-24. Pre-cutover bars were ±10 %.
> This resolver does not currently take `trade_date` so it always returns ±20 % for 300/301.

其规则表标题为「effective 2024+」。对 2018–2026 回测的错误面：创业板 2018-01 至
2020-08 全段、科创板 2019-07 前不存在、北交所 2021-11 前不存在，
另有新股上市首日与退市整理期规则未覆盖。

**改为读数据基础设施的 `daily_price_limit` 表**（来自 Tushare `stk_limit`，
含逐日 `up_limit`/`down_limit`）。`limit_pct_resolver` 保留供生产实时路径使用——
其规则对 2024+ 正确，不必改动，也不应为回测去改它。

### 7.3 停牌

现行 `get_forward_bars_with_meta` 用 `gap_too_long` 把跨越长时间的窗口判为抑制样本
（`stock_repo.py:249`）。直接抑制会引入偏差——**停牌与坏消息正相关**，
抑制等于选择性删除坏结果。

处置改为：

- **持有期按交易日计，不按自然日**，停牌期间穿透持有，复牌后继续计数。
- 停牌判定读数据基础设施的 `suspension_history` 表（来自 Tushare `suspend_d`），
  不再依赖 `gap_too_long` 这种由数据缺口反推的启发式——后者无法区分
  「真停牌」与「抓取失败」。
- 记录 `suspension_days` 作为协变量。
- 同时报告「抑制停牌样本」与「穿透持有」两套结果作为敏感性检验，
  二者差异过大时在报告中显式提示。

### 7.4 退市（v3 完全缺失，且现行逻辑有偏）

持有期内退市的股票，前向 bar 直接断供，落入 `insufficient_bars` 被判为抑制样本。
**这等于把退市造成的亏损丢弃，而不是实现它**——幸存者偏差在收益侧的复发，
比宇宙侧的更隐蔽。

处置：

- 用 `delist_date`（数据基础设施 G1）区分两种断供：
  - `date ≥ delist_date` → **退市清算**，不是数据缺失
  - 其他原因断供 → 数据缺失，维持抑制
- **退市清算规则**：按可得的最后一根 bar 收盘价清算并计入收益。
  A 股退市整理期为 30 个交易日，若该股进入整理期，用整理期最后收盘价。
- 标记 `delisted_during_holding`，并单独报告该类样本的数量与收益分布。
- 验收：退市样本的收益必须为负向占多数；若被大量判为「数据缺失」而抑制，说明规则未生效。

### 7.5 配股：一笔至今无归宿的现金流（v6 补齐，P0-6）

数据基础设施 6.6 声明了复权约定为「假定全额参与配股」，并写「由回测侧决定是否覆盖处理」——
**而本设计此前从未接手**。后果是 `close_adj` 的收益序列隐含一笔
**组合里并不存在的资金注入**：复权价假设投资者按配股价缴款，
用它算被动持有收益必然高估。

数值上不是小事。以 10 配 3、配股价 5 元、前收 10 元为例，
除权参考价 `(10 + 0.3×5)/1.3 = 8.846`，复权序列显示当日收益 0，
而不参与配股者实际按 8.85 计价，承受约 11.5% 的摊薄。

#### v7 修正：整条剔除不可行，改为除权日前一交易日强制平仓

v6 定稿为「整条剔除」。实测审计指出该方案**需要追溯重算此前组合**——
在日历时间组合里，该持仓在配股公告前的每一天都已经贡献了 `R(d,k)`，
事后剔除等于回头修改历史逐日收益。两个后果都不可接受：

1. 组合构造不再是单遍前向计算，必须两遍（先扫全部配股事件再算组合）。
2. 更严重的是**语义**：d 日的组合成分取决于 d 之后才发生的事件，
   这个组合在现实中不可持有，整条序列失去可交易性。

**改为：在配股除权日的前一交易日按收盘价强制平仓，状态机记 `exit_rights`。**

这个方案同时解决三个问题：

- **因果性**：配股方案（股权登记日、除权日、配股价）在除权日前已公告，
  「除权日前一日清仓」在现实中可执行，不含未来信息。
- **无需现金账户**：在除权发生前就退出，根本不触及配股缴款，
  6.6 的资金注入问题自然消失。
- **单遍计算**：不需要回头改任何已算出的 `R(d,k)`。

代价是持有期被截断，该样本不再有完整的 k 日收益。因此：

- **日历时间组合（主指标）不受影响**——它本就是逐日平均，提前退出只是少几天持仓。
- **事件时间的 `forward_return_k`（辅助指标）该样本作废**，标 `truncated_rights`
  并从 k 日收益统计中排除。
- 两处口径不同必须显式声明，避免读者以为同一批样本。

依赖与验收：

- 判定依据是数据基础设施 `corporate_actions` 表的 `rights_ratio` 非空
  （其 7.6f 已改为版本化产物），**漏标即漏平仓**，召回率纳入该项目验收 #34。
- 本设计报告 `exit_rights` 的样本数与占比。占比过高时须重新评估
  ——那说明配股在样本中并不稀有，截断带来的持有期分布扭曲不可忽略。

## 八、统计推断框架

### 8.1 原始样本量是幻觉

回补后预计约 1820 个可用信号日，每日约 7 条候选，原始样本约 1.3 万。
但该数字不能用于显著性检验：

- **横截面相关**：同一天选出的股票同涨同跌，远非独立观测。
- **时序重叠**：k 日持有期使相邻 k 天的样本共享收益区间。

### 8.2 日历时间组合：观测单位是「持有日」，不是「信号日」

**v4 此处名实不符，予以更正。** v4 写的是「对每个信号日 T，把当日全部候选等权合成组合，
计算其 k 日前向收益，得序列 `{R_T}`」——这是**事件时间的重叠窗口构造**，不是日历时间组合。
它只消解了 8.1 的横截面相关，**没有消解时序重叠**：`R_T` 与 `R_{T+1}` 共享 k−1 天的收益，
序列自相关是构造性的。v4 却在 8.1 把时序重叠列为必须解决的问题，前后矛盾。

#### 正确构造

日历时间组合（Jaffe–Mandelker / Fama 口径）的做法是**换一个索引轴**：

```text
对每个日历交易日 d：
  持仓集合 H(d, k) = { 股票 i : i 在 d 日处于 holding 状态 }（状态机见 8.2b）
  R(d, k)  = mean_{i ∈ H(d,k)} r_i(d)        -- r_i(d) 是 i 在 d 日的单日收益
```

得到的 `{R(d,k)}` 是**单日收益序列，天然不重叠**。时序重叠被构造消解，
而不是留给 block bootstrap 去补救。block bootstrap 此时只需处理残余的自相关
（波动率聚集等），任务轻得多，区间也更可信。

#### 三个必须写死的构造细节

实施时不写死，不同人会给出不同结果：

1. **重复入选的权重**：同一股票在 k 日窗口内多次发出信号时，
   **按股票等权而非按信号等权**（即 `H(d,k)` 是集合，去重）。
   按信号等权等价于对高频复选的股票加杠杆，会把「策略反复看好某股」
   误计为「该股权重更高的组合收益」。
2. **空仓日**：`H(d,k)` 为空的日子记 `R(d,k) = 0`（等价于持有现金），
   而不是从序列中剔除。剔除会系统性偏向「有信号的时段」，
   而信号密度本身与市场环境相关。空仓日占比须单独报告。
3. **T+1 起点**：`H(d,k)` 的窗口为 `[d-k, d-1]`，信号日 T 的股票最早在 d = T+1 计入，
   与 7.1 的 T+1 口径一致，收益不含信号日当日涨跌。

### 8.2b 持仓状态机（v6 新增，P0-4）

v5 把 `H(d,k)` 定义为「`[d-k, d-1]` 内发过信号的股票」，
**默认每条信号都在 T+1 成为持仓**——这与 7 节的成交与生命周期规则脱节。
7 节定义了涨跌停受阻、停牌、退市三类情形，但从未接入组合构造，
等于规则写了却不生效。

持仓必须由显式状态机决定：

| 状态 | 进入条件 | 是否计入 `H(d,k)` | 当日收益 |
| --- | --- | --- | --- |
| `pending` | 信号日 T 收盘后 | 否 | — |
| `entry_blocked` | T+1 开盘涨停（`daily_price_limit` 判定），无法买入 | 否 | — |
| `entry_abandoned` | 连续 `max_pending_days` 日受阻仍未入场 | 否（终态） | — |
| `holding` | 成功以 T+1 开盘价入场 | **是** | `r_i(d)` |
| `suspended` | 持有期内停牌（`suspension_history`） | **是** | **0（价格未变）** |
| `exit_blocked` | 到期日跌停无法卖出，顺延 | **是** | 延续日公式，**亏损照实现** |
| `closed` | 持满 k 个交易日并以 `open` 卖出 | 否（终态） | — |
| `liquidated` | 持有期内退市，按最后可得收盘价清算 | 否（终态） | — |
| `exit_rights` | 配股除权日前一交易日强制平仓（见 7.5） | 否（终态，持有期截断） | — |

#### 四条必须写死的判定

1. **`entry_blocked` 不计入组合。** 这是最关键的一条：涨停买不到的信号从未成为持仓，
   把它计入等于统计一笔不存在的交易。而且这类样本**系统性偏向表现最好的候选**
   ——T+1 开盘涨停的股票恰恰是动量最强的那些——不剔除会系统性高估收益。
2. **`max_pending_days` 须显式取值**（建议 1，即 T+1 买不到即放弃，
   与「信号在 T 日有效」的语义一致）。取值写入 `config_json`。
3. **`suspended` 计入且收益记 0**，而非从当日组合中剔除。剔除会让组合在停牌期间
   隐性重新加权到其余持仓上，等价于一次未发生的调仓。
4. **`k 个交易日`按 `holding` 与 `suspended` 合并计数**，与 7.3 的「穿透持有」一致；
   `pending` 不计入持有期。

### 8.2c 逐日收益公式（v7 定稿）

v6 定义了状态机但**没写出任何一条收益公式**，`r_i(d)` 与基准收益都停留在符号层面。
实测审计要求精确定义首日、延续持仓与市场中位数三处。以下为定稿。

#### 成交约定

入场 `open(T+1)`，出场 `open(T+1+k)`。两端都用开盘价，口径对称。

#### 个股逐日收益

| 持有日 | 公式 | 说明 |
| --- | --- | --- |
| **首日** `d = T+1` | `close(T+1) / open(T+1) − 1` | **不是全日收益**。以开盘价买入，当日只赚到开盘到收盘那一段 |
| **延续日** `T+2 ≤ d ≤ T+k` | `close(d) / close(d−1) − 1` | 常规日收益 |
| **出场日** `d = T+1+k` | `open(d) / close(d−1) − 1` | 只持有到开盘，即隔夜跳空那一段 |
| **停牌日** | `0` | 价格未变（8.2b 细节 3） |

三段连乘恰好等于 `open(T+1+k) / open(T+1) − 1`，与成交约定自洽。
这个恒等式是实现的**自检条件**，须写成单元测试。

**首日公式是最容易写错的一处**：直接用 `close(T+1)/close(T)−1` 会把信号日收盘到
次日开盘的跳空计入收益，而那段行情在下单时点尚不可得，属未来信息。
7.1 的 T+1 约定只有配上这条公式才真正成立。

#### 组合逐日收益

```text
R(d, k) = mean_{i ∈ H(d,k)} r_i(d)
```

等权，`H(d,k)` 由 8.2b 状态机给出。空仓日 `R(d,k) = 0`。

#### 市场中位数基准

主基准（9.3）的逐日收益定义必须与策略腿**逐字对齐**，否则差值无意义：

```text
B(d) = median_{i ∈ U(d)} [ close(d) / close(d−1) − 1 ]
```

`U(d)` 的界定（三条缺一不可）：

1. **d 日在市**：`list_date ≤ d` 且（`delist_date` 为空或 `d < delist_date`）。
2. **d 日有成交**：当日在 `stock_daily` 有行且非停牌。停牌股不计入中位数
   ——它们收益恒为 0，计入会把基准向 0 拉。
3. **上市满 N 个交易日**：新股上市初期波动极端，会污染中位数。
   N 取值写入 `config_json`，建议 60。

**基准用「延续日公式」而非分段公式**，因为基准是一个持续持有的参照物，
没有入场出场时点。这是策略腿与基准腿唯一允许的公式差异，须显式声明。
其代价是首日与出场日的比较不完全同口径——影响量级为两个半日收益，
须在实施计划中评估是否需要对基准也做半日切分。

#### 必须报告的状态统计

`entry_blocked` / `entry_abandoned` / `exit_rights` / `liquidated` 四类的样本数与占比
须作为报告的一等内容。它们共同构成「信号有效性」与「可交易性」之间的落差，
是 11.1 判断 free 模式结论边界的直接依据。

#### 事件时间口径不废弃，但降级为辅助

前向收益 `forward_return_k` 仍需保留——它是逐样本的、可与 `setup_type` 等
协变量交叉分析的粒度，8.4 的 Rank IC 也依赖它。
但**主指标只用日历时间口径**，事件时间的结果标为描述性。

### 8.3 置信区间：block bootstrap，且**不做 `n_eff` 二次缩放**

对 8.2 的 `{R(d,k)}` 做 moving block bootstrap，块长 `max(k, 20)` 个交易日，
重采样 2000 次，取分位数作为置信区间。

块长取 `max(k, 20)` 的理由在 v4 的重叠构造下是「覆盖重叠窗口」；
改用日历时间组合后重叠已被构造消解，块长的作用变为覆盖残余自相关与波动率聚集，
`20` 个交易日（约一个月）是保守取值。**这一变化须在实施计划中重新论证块长选择**，
不能沿用 v4 的理由。

**v3 此处自相矛盾，予以更正**：v3 同时要求「置信区间基于 `n_eff`」与
「bootstrap 取分位数」。分块自助法在重采样时**已经把序列自相关计入**，
若再用 `n_eff` 缩放一次即为重复惩罚，区间被撑宽，真实有效的信号会被误判为不显著。

**`n_eff` 的正确定位：仅作诚实性披露的诊断量，不参与任何区间计算。**

- 报告中必须同时给出原始样本数与 `n_eff ≈ 持有日数 / k`（k=10、约 1820 个交易日时约 182），
  用途是防止用 1.3 万这个数字制造统计错觉。
- 区间**完全**由 bootstrap 给出。
- 不使用 iid 假设下的 t 检验。

### 8.4 Rank IC

每个信号日计算候选打分（用 5.2 修复后的 `raw_rule_score`）与前向收益的 Spearman 秩相关。

- 报告 IC 均值、标准差、ICIR、IC > 0 的日占比。
- 显著性用 8.3 的 bootstrap。
- **注意**：日内候选数中位数约 7，秩相关在 n=7 上噪声极大。须同时报告
  「按日 IC 分布」与「合并全样本的分层收益差」两个视角，
  单看 IC 均值会被小样本噪声主导。

### 8.5 分层分析的可行性边界

按 `setup_type`（5 类）× `market_regime`（3 类）分层后单格约 121 个信号日。

**分层结果只做描述性展示，不做显著性断言。** 这是数据跨度决定的硬约束，
分析方法无法绕过。设计中写死，避免实施时被「再切细一点看看」破坏。

### 8.6 多重比较

主结论只认**预先声明的单一主指标**，其余全部标为探索性。
预先声明内容写入 run 的 `config_json`，运行后不可修改。

**主指标定稿**：`leg = strategy`、`holding_period_days = 5` 的日历时间组合收益，
减去同期市场中位数组合收益（基准选择理由见 9.3）。
`k = 5` 与「腿 = strategy」都必须显式写入声明，
因为 10.3 的表按 `(leg, holding_period_days)` 分维度存储，不写死等于没声明。

## 九、消融与对照

### 9.1 消融必须是判定器旁路，不是常量入参（v6 修正）

v3 写「关闭各层」语义不成立；v4/v5 改成「中性替代值」**仍然不成立**，
只是错得更隐蔽。代码结构说明了原因。

#### 各层实际上是「标注器 + 下游闸门」

`five_layer_pipeline.py` 的实际流程：

```text
L2 theme_resolver.resolve()      → tp          （标签）
L3 pool_classifier.classify(theme_position=tp, ...) → pool_level  （标签）
L4 → entry_mat                                       （标签）
L5 stage_judge.judge(setup_type, entry_maturity, pool_level,
                     theme_position, has_stop_loss)   → trade_stage
   ↓
   kept / vetoed 按 trade_stage 切分（:633-634）
   ↓
   rule_score = _STAGE_PRIORITY + _POOL_PRIORITY + _THEME_PRIORITY + ...（:661-664）
```

即 **L2/L3/L4 产出标签，真正的过滤发生在 L5**，标签还二次进入排序。

#### 为什么「中性替代值」不是消融

给 `pool_level` 灌一个常量，L5 的 `judge` **仍然在按 pool_level 做门限判定**，
只是所有候选拿到同一个门限结果。这不是「移除 L3 的作用」，
而是「把 L3 换成一个退化的 L3」。

致命之处在于**结果完全由所选常量决定**：

- 灌最低档（`WATCHLIST`）→ L5 几乎全否决 → 结论「L3 极其关键」。
- 灌最高档 → L5 几乎全放行 → 结论「L3 是负担」。

两个结论都是常量选择的产物，不是 L3 贡献度的测量。
对有序标签喂进门限判定的结构，**不存在中性值**——每个取值都是一项策略选择。

#### 正确做法：在判定器内部旁路该条件

消融必须实现为 `TradeStageJudge` 与 `CandidatePoolClassifier` 接受一个
**逐条件旁路集合**，被旁路的条件不参与判定，而不是参与判定但取常量。

| 实验 | 实现 | 语义 |
| --- | --- | --- |
| 去 L1 | `judge` 忽略 `env`，且不做环境级过滤 | 环境闸门移除 |
| 去 L2 | `judge` 与 `classify` 均忽略 `theme_position`；排序项 `_THEME_PRIORITY` 置 0 | 题材闸门与题材加权同时移除 |
| 去 L3 | `judge` 忽略 `pool_level`；`_POOL_PRIORITY` 置 0 | 池级闸门与加权移除 |
| 去 L4 | `judge` 忽略 `entry_maturity` | 买点成熟度闸门移除 |
| **去 L5** | — | **不可定义**，见 9.2 |

**排序路径必须一并旁路**（`:661-664`）。只旁路闸门而保留 `_POOL_PRIORITY` 加权，
等于「L3 不再决定去留但仍决定优先级」，是个既非全开也非全关的第三种策略。

#### 旁路会显著改变候选规模，必须控制

闸门移除后候选数上升（幅度未知，须实测）。这带来两个连带要求：

1. `backtest_daily_portfolio.n_positions` 在消融 leg 上会与基准 leg 差异很大，
   **不能直接比较依赖持仓数的量**。主指标为等权组合日收益，
   对持仓数不敏感，可比；但夏普、最大回撤这类量不可直接比。
2. 须同时报告各消融 leg 的候选数与其相对基准的倍数，
   若某层旁路后候选数暴涨一个数量级，该 leg 的结论只作方向性参考。

旁路开关的具体实现位置与签名在实施计划中给出，并记入 `ablation_config_json`。

### 9.2 L5 无法消融，改为阶段间收益差异

L5 产出的 `trade_stage` **就是被评估的信号本身**，关掉之后没有信号可评，
「去 L5」是空实验。

替代设计：**比较 L5 各交易阶段之间的收益差异**，直接回答「阶段划分是否有区分度」。

- 度量：`probe_entry` / `add_on_strength` / `focus` / `watch` 各阶段的
  日历时间组合收益，两两差值及其 bootstrap 区间。
- 若阶段间无显著差异，说明 L5 的阶段划分不携带信息——这与「消融后变差」等价，
  但语义是良定义的。
- 附加检验：随机打乱 `trade_stage` 标签重跑，作为该项的负控制。

### 9.3 对照组

- **不使用「被否决候选」**：否决是策略的输出，用它做对照引入选择偏差——
  被否决的股票在被否决那一刻起就不是随机样本。
- **风格中性对照**：按市值分位 + 行业匹配的随机抽样组合。
  **行业匹配必须用 6.3 历史化后的行业**，否则对照组本身带未来信息。
- **市场中位数**：当日全市场收益中位数，最粗但最稳健的兜底基准。
- **指数基准**：沪深300 与中证2000，各自独立成 `leg`，仅作展示参照。

#### 主基准必须唯一且不可降级（v4 此处三处自相矛盾）

v4 在三个地方给出了不一致的说法：9.3 列了四个候选基准并说主指标减去风格中性组，
8.6 说主指标是「日历时间组合超额收益」但未指明相对谁，
10.3 的表只留了单列 `benchmark_return_k`。实施时必然各取一说。

**定稿：主基准 = 市场中位数，主指标 = 日历时间组合收益 − 当日全市场收益中位数。**

选它而不选风格中性组的理由是**可降级性**：

| 基准 | 依赖 | 未购积分时 |
| --- | --- | --- |
| 市场中位数 | 仅需 `stock_daily` | **可用** |
| 风格中性组 | 历史市值（阶段 H）+ 历史行业（阶段 G2） | 不可用 |
| 指数基准 | `index_daily`（阶段 H） | 降级到 akshare |

v4 把主指标定义在风格中性组上，等于**让整个回测的主结论悬在付费依赖上**——
积分未购或三天窗口内拉取失败，主指标即无法计算，项目无结论可交付。
市场中位数虽然粗糙（不控制市值与行业暴露），但零依赖、口径无歧义、不会失败。

风格中性组降级为**主要的稳健性检验**：主结论用市场中位数，
风格中性组的结果作为「效应是否只是市值/行业暴露」的证伪尝试并列报告。
若二者结论方向相反，须在报告中显式提示而非择优呈现。

### 9.4 正负控制

正负控制是**框架自身的验收项**，必须在解读主结论之前先通过。

#### 负控制

- **随机选股组合**：每日随机抽取与策略候选数相同的股票，主指标应不显著异于 0。
- **标签打乱**：随机打乱 `trade_stage` 后重跑 9.2 的阶段间差异，应不显著。
- **泄漏探针**：6.6 的探针字段未被访问。

#### 正控制不能用真实动量因子（v4 此处会给出错误信号）

v4 提议用「20 日收益率排序」作正控制，期望其显著为正。**这个前提在 A 股不成立**——
A 股短周期以反转效应为主，20 日动量做多在多数区间收益为负或不显著。
用它作正控制，「不显著为正」是该因子的正常表现，而非框架失灵，
框架会因此被误判为「灵敏度不足」。

更根本的问题是：**没有任何简单因子在 2018–2026 全期稳定有效**。
小市值 2018–2020 有效、2021 后失效；反转在不同区间强度差异极大。
选真实因子作正控制，等于把框架验收绑定在一个本身不确定的经验事实上。

**改为注入已知强度的合成效应（功效检验）：**

```text
合成信号 = 每日随机选股，但在选股概率中注入一个已知大小的未来收益倾斜
          即以概率权重 ∝ exp(λ · r_future_k) 抽样，λ 控制效应强度
```

- 该信号**按构造必然有效**，效应强度由 λ 精确控制，无需依赖任何经验假设。
- 扫描若干 λ 值，给出「框架能以 80% 功效检出的最小效应」这一数值。
- 该数值是解读主结论的必要前提：若主策略的点估计低于该阈值，
  「不显著」只说明**样本量不足以分辨**，不构成「策略无效」的证据。

这与 6.6 的泄漏探针形成对称——探针检验「不该泄漏的没泄漏」，
合成信号检验「该检出的能检出」。二者都是构造性的，不依赖市场经验。

合成信号的实现**必须与主管线共用同一套统计层与对照组**，
否则检出的是另一条代码路径的灵敏度。

### 9.5 样本外验证：v4 把方向写反了

v4 写「2018-01 至 2023-12 为开发期，2024-01 至今为验证期」。**这是颠倒的，
而且颠倒的方向恰好是回测中最经典的自欺——用样本内数据做最终验证。**

事实是：库内现存的 561 个交易日就是 2024–2026，而那正是五层策略**实际生产运行的时段**。
策略的规则、阈值、层级划分都是在观察这段时间的表现中形成和调整的。
2018–2023 则是本项目即将回补的数据，策略从未见过。

| 区间 | 性质 | 用途 |
| --- | --- | --- |
| 2024-01 至今 | **样本内**（策略开发与调参期） | 只用于确认管线正确性，不作效力证据 |
| 2018-01 至 2023-12 | **保留期**（held-out，策略未见过） | 一次性验证，结果不可回退修改 |

- 参数选择与指标筛选只允许在样本内区间进行。
- 保留期只跑一次，结果无论好坏均写入报告。
- **禁止**看到保留期结果后回头调整任何设定。若确需调整，必须作为新的一轮
  并在报告中记录「这是第几次看保留期」——多看一次，其样本外性质就削弱一分。

#### 保留期也不是真正的样本外

必须诚实声明这一点：2018–2023 的市场走势对设计者是已知的
（2018 熊市、2019–2020 结构性牛市、2021–2022 下跌、2023 震荡），
策略规则的设计不可避免受此背景影响。这是**伪样本外**，
只能排除「在该段数据上直接调参」这一层过拟合，无法排除更高层的知识渗透。

**真正的样本外只能是前瞻跟踪**：设定冻结后向前记录实盘或纸上交易信号。
本项目不提供真样本外结论，报告须显式写明这一边界，
避免保留期的良好结果被解读为「已验证有效」。

### 10.2 新增表 `backtest_replay_candidates`

历史重放生成的候选，结构对齐 `screening_candidates` 但独立成表，带 `backtest_run_id`。

**不得写入生产 `screening_candidates`**——重放产物污染生产表会让

### 10.3 新增表 `backtest_daily_portfolio`

日历时间组合的逐日序列，是 8.2/8.3 的直接输入，也是复现的关键中间产物。

**v4 的字段设计缺两个维度，予以更正。** v4 字段为
`(backtest_run_id, trade_date, n_candidates, portfolio_return_k, benchmark_return_k,
excess_return_k, ic_spearman)`，主键只能是 `(run_id, trade_date)`。
字段名里的 `_k` 暗示某个持有期，但**表中没有 k 这一列**——
而 8.6 的主指标用 k=5、8.3 的示例用 k=10、8.4 的 IC 要多个 horizon，
多个 k 无法共存。同样缺失的是「腿」维度：9.2 要比较 L5 四个交易阶段，
9.3 要三类对照组，9.4 要正负控制，这些都是并列序列。

修正后的主键：`(backtest_run_id, leg, holding_period_days, trade_date)`。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `backtest_run_id` | INTEGER | — |
| `leg` | TEXT | 序列身份：`strategy` / `stage:probe_entry` / `stage:focus` / `control:style_neutral` / `control:market_median` / `control:index_hs300` / `control:random` / `control:injected_effect` / `ablation:no_l1` 等 |
| `holding_period_days` | INTEGER | 8.2 的 k |
| `trade_date` | TEXT | **持有日 d，不是信号日 T**（见 8.2） |
| `n_positions` | INTEGER | `\|H(d,k)\|`，v4 的 `n_candidates` 语义是信号日候选数，与新构造不符 |
| `portfolio_return` | REAL | `R(d,k)` |
| `is_empty_day` | INTEGER | 空仓日标记（8.2 细节 2） |

`benchmark_return` 与 `excess_return` **不再作为列**——基准本身就是一条 `leg`，
差值在读取时计算。v4 把基准塞进同一行意味着基准唯一，与 9.3 的多对照组冲突。

`ic_spearman` 移出本表：IC 是**信号日**粒度的量（8.4），
与本表的持有日粒度不同轴，混在一起会让主键语义混乱。
另立 `backtest_daily_ic`，键为 `(backtest_run_id, trade_date, horizon_days)`。

### 10.5 数据不可变链路与 `run_data_manifest`（v7 新增）

v6 只有若干版本字段，不足以保证复现。问题在于**数据本身是活的**：
日常同步持续写 `stock_daily`，C2 会整表提升，`corporate_actions` 会随信源升级换版本。
一次运行结束后，它读过的数据可能已经不存在了。

因此在重放前建立一条不可变链路：

```text
copy  → 从生产库切片出本次运行所需数据，写入只读快照
hash  → 对每张表按规范化字节序算摘要
export→ 快照落盘为独立文件，与运行产物同生命周期
run_data_manifest → 记录快照路径、逐表摘要、行数、时间窗、各产物版本号
```

`run_data_manifest` 的内容（与 `five_layer_backtest_runs` 一对一）：

| 字段 | 说明 |
| --- | --- |
| `snapshot_path` | 只读快照位置 |
| `table_hashes_json` | 逐表摘要，键为表名 |
| `row_counts_json` | 逐表行数，摘要不匹配时用于快速定位 |
| `date_range` | 数据时间窗 |
| `adj_table_version` | `stock_daily_adj` 版本 |
| `corporate_actions_version` | `corporate_actions` 的 `version`（数据基础设施 7.6f） |
| `st_industry_version` | `instrument_status_history` 版本 |
| `code_revision` | 代码 git revision |
| `config_hash` | 含 8.6 预先声明与 8.2b 的 `max_pending_days` 等全部参数 |

三条硬要求：

1. **重放只读快照，不读生产库。** 这与 6.2 选定的 `isolated_replay_database`
   方案天然一致——该函数本就在做 copy，此处只是把 hash 与 manifest 补上，
   并让快照可留存而非用完即删（现实现用 `TemporaryDirectory`，见 `dataset.py:241`）。
2. **两次运行的可比性由 manifest 判定，不由人工回忆。** 验收 #15 的
   「是否可比」改为逐字段比对 manifest 并给出差异清单。
3. **快照的保留策略须定**（保留最近 N 次或按运行标记保留），
   实施计划给具体数字——全期快照体积可观，不能无限累积。

### 10.4 新增表 `instrument_status_history`

ST 与行业的历史版本（6.3）。字段：`code`、`status_type`（`st`/`industry`）、
`value`、`start_date`、`end_date`、`source`。归属数据基础设施项目落地。

### 11.0 J 是历史候选生成的前置，不只是 F（v6 修正，P0-3）

v5 把依赖写作「A0–F + G1 + C2」，**漏了 J**。这不是排期细节，是结论有效性问题。

F 只是把复权价**物化**到 `stock_daily_adj`；
**J 才是让因子链路真正去读它的那一步**（数据基础设施 6.7 列了 11 个 detector 的改造面）。
J 未完成时 `FactorService.build_factor_snapshot` 仍从不复权 `close` 计算均线、
动量、突破比与各类形态。

后果：历史重放会把除权假断层**复制到 2018–2026 全窗口的每一条候选上**。
数据基础设施 1.1 已实测该失真的形态——每年 6–7 月分红季全市场技术因子集体扭曲，
典型案例 001229 的除权假跳空被识别为「底背离双突破 confirmed」。
在这样的因子上跑出的候选，无论统计层多严谨，衡量的都是「带 bug 的策略」。

因此**确认性回测在 J 完成前不得开工**。可以先做的是阶段 0（前置修复，
不依赖数据）与阶段 1 的接口设计，但不得跑出任何用于下结论的历史候选。

顺带一个边界：依赖的是 **J（能力可用）而非 L（生产默认翻转）**。
回测可在自己的 `config_json` 中置 `ADJ_ENABLED=true`，
不必等生产默认值翻转，二者解耦。

### 11.3 算力预算：82.4 小时是实测数字，不是估算（v7 新增）

实测审计给出：**500 股单日因子耗时 14.822 秒**，按当前串行实现外推全期
（5580 股 × 约 2080 交易日）约 **82.4 小时**。

v6 把算力风险的缓解写成「复用既有因子缓存与并行」，那是个愿望不是方案。有了实测数字后：

#### 因子计算必须与层级判定解耦

这是把 82 小时从「每条 leg 一次」变成「全项目一次」的关键。

消融（9.1）、对照组（9.3）、正负控制（9.4）加起来有十余条 leg，
但它们**只改变 L1–L5 的判定，不改变因子本身**。
因此因子快照必须计算一次并落 `ValidationFactorCache`，
所有 leg 从同一份缓存重放判定层。

- 若架构上做不到解耦，十余条 leg × 82 小时 = 上千小时，项目在算力上直接不可行。
- 既有 `ValidationFactorCache.from_database(...)` 已带 `workers` 参数
  （`bottom_divergence_v2_cli_service.py:422-431`），说明解耦在既有底座上已部分成立，
  **但必须在阶段 1 显式验证**：跑两条 leg，确认第二条不重算因子。

#### 并行与分批

- `workers=4` 时约 20.6 小时，仍需跨夜运行，**必须有检查点断点续跑**
  （复用 `CanonicalCheckpointStore`）。
- 实施计划须先在 1 个月窗口上实测并行加速比，再据此定 worker 数与分批粒度，
  不得直接按线性加速外推。

#### 对开工顺序的影响

因子全量计算是**不可压缩的一次性成本**，且依赖数据基础设施 J（11.0）。
因此它不能与 J 并行，只能串在其后。这条链路是项目工期的下界：

```text
数据 A0→C→C2→E→F→J  →  因子全量计算（20+ 小时）  →  各 leg 重放（廉价）
```

### 11.1 付费依赖的降级边界（v5 补齐）

v4 只在阶段 6 标了积分依赖，遗漏了 2b 与 3b。完整清单与降级后果：

| 阶段 | 付费依赖 | 未购积分时 |
| --- | --- | --- |
| 2b 指数源 | `index_daily` | 降级到 akshare 免费拉取；**不可跳过**，否则 L1 无数据 |
| 3b 涨跌停 | `daily_price_limit` | **无免费替代**。规则重建对 2018–2023 系统性错误（7.2），只能标注该期涨跌停判定不可用并在报告中声明 |
| 3b 停牌 | `suspension_history` | 无权威停牌源，8.2b 的 `suspended` 状态不可靠；穿透持有与抑制两套敏感性检验的差异无法归因 |
| 6 风格中性组 | `stock_daily_basic` + `instrument_status_history` | 主基准已改为市场中位数（9.3），**主结论仍可交付**；风格中性组作为稳健性检验缺席，须声明 |

### 11.2 free 模式的结论边界：有预测力 ≠ 可交易（v6 修正，P0-5）

v5 写「未购积分时项目仍有主结论可交付」，**这句话需要限定，否则会被误读**。
free 模式能算出主指标，但那个数字回答不了「这个信号能不能赚钱」。

#### 缺失 `daily_price_limit` 的后果是有方向的偏差

8.2b 的状态机依赖涨跌停判定来剔除 `entry_blocked`。free 模式下无历史涨跌停价，
只能退回 `resolve_limit_pct` 的规则重建，而它对 2018–2023 系统性错误（7.2）：
创业板 2018-01 至 2020-08 实际 ±10% 却按 ±20% 判定，
意味着真实涨停的 bar **不会被识别为涨停**。

#### v7 修正：偏差方向不是统一乐观，而是不可知

v6 写「偏差方向是系统性乐观的」。**实测审计推翻了这个判断的普适性**：

> 创业板 15% 涨幅当前被默认主板规则（±10%）判为涨停。

即 `resolve_limit_pct` 在实际调用中未走到 `300/301 → ±20%` 分支，
而落到了 `DEFAULT_A_SHARE_LIMIT_UP_PCT = 10.0` 兜底。这是**相反方向**的错误：

| 方向 | 机制 | 后果 | 偏差 |
| --- | --- | --- | --- |
| 漏判 | 返回 ±20% 而历史实为 ±10% | 真涨停未识别，买不到的样本被计入 | **偏乐观** |
| 误判 | 板块解析失败兜底 ±10%，实为 ±20% | 15% 正常涨幅被当涨停，买得到的强势样本被剔除 | **偏悲观** |

两个方向同时存在，**净方向取决于两类样本的相对数量，在接入 `stk_limit` 前不可知**。

这比「统一偏乐观」更糟：单向偏差至少可以说「真实值不会比这个更好」，
而方向不明意味着 free 模式的收益数字**连一个可靠的界都给不出**。
偏差幅度同样测不准——用于估算它的涨停占比本身就来自那套错误规则。

#### 三条同时缺失的可交易性依据

| 缺失 | 影响 |
| --- | --- |
| 历史涨跌停 | 无法剔除买不到的信号，收益系统性高估 |
| 历史停牌 | 持有期计数与穿透规则退化，`suspended` 状态不可靠 |
| 配股标记完整性 | 7.5 的平仓依赖 `corporate_actions.rights_ratio`，其召回率同样待验 |

#### 结论定位

| 模式 | 可支持的结论 | 不可支持的结论 |
| --- | --- | --- |
| free | **信号是否具有统计预测力**（Rank IC、分层收益差、方向性） | 可交易性、真实收益水平、能否落地 |
| 付费 | 上述全部 + 可交易性与收益水平 | 真样本外（9.5） |

**free 模式的产出必须在报告中显著标注为「研究性结论，不可用于交易决策」，
并写明偏差方向不可知。** v5 的表述「主结论仍可交付」据此收紧。

#### 机器可执行闸门，不能只靠文档约定（v7 新增）

前述限定若只写在文档里，实施与解读时必然被跳过。改为**代码级闸门**：

运行开始时按 `run_data_manifest`（10.5）判定模式：

```text
paid 模式 ⟺ daily_price_limit、suspension_history、stock_daily_basic、
            instrument_status_history 四张表在快照中均非空且覆盖率达门槛
否则为 free 模式
```

两条强制行为：

1. **free 模式下，涉及可交易性的指标不予计算也不予输出**——
   不是算完打个标签，而是根本不产出。具体包括：绝对收益水平、
   `entry_blocked` 相关统计、任何以「元」或「%收益」呈现的可执行数字。
   free 模式只输出 Rank IC、分层收益**差**、方向性判定这类相对量。
2. **报告头部由程序写入模式标识与缺失表清单**，非人工填写。
   CLI 退出码区分两种模式，便于外部流程拦截。

模式判定结果写入 `run_data_manifest`，使「这个结论是哪种模式下得出的」
成为运行产物的一部分而非事后追溯。

这也构成购买积分的最终理由：项目的目的是验证选股信号能否指导交易，
而 free 模式在定义上答不了这个问题。

**设计目标据此修正为：未购积分时项目仍能交付一个「信号有无预测力」的可证伪结论，
但不能交付可交易性结论。** 9.3 把主基准改为市场中位数是为了守住前者，
而非声称后者也能达成。

**交付形态**：首版为 CLI 报告，不做 Web UI。研究阶段迭代频繁，
CLI 改动成本远低于前后端联调，且报告内容尚未稳定。Web 化在结论稳定后另行评估。

| **主题成分不可 as-of 化** | L2 无法验证 | 默认关闭；开启结果仅作偏差上界；写入报告局限性 |

| 重放引擎参数化触及 v1/v2 既有路径 | 既有验证功能回归 | 参数化保持默认行为不变；v1/v2 现有测试作为回归门 |
| `isolated_replay_database` 全量拷贝成本 | 重放耗时不可接受 | 实测成本；超阈值再评估 6.2 方案 B |
| 止损解析统一大幅改变推送内容 | 用户可见 | 带开关灰度；切换前后分布对比 |
| 历史重放算力成本 | 项目停滞 | 复用既有因子缓存与并行；检查点断点续跑 |
| 样本量不足以支撑分层结论 | 期望落空 | 8.5 已写死边界；正控制作为灵敏度下界的客观判据 |
| 结论为「信号无效」 | 心理预期 | 这是有效的研究结果；正负控制确保该结论可信而非框架缺陷 |
| **隔离库缺表静默降级** | **时点正确性失效且无告警** | **启动自检 + 验收 #19 反例测试** |
| **指数覆盖不足** | **保留期 L1 全程无数据，项目无法进行** | **阶段 2b 切换读取源；验收 #20** |
| **保留期被多次查看** | **样本外性质逐次削弱** | **记录查看次数并在报告中披露；9.5 写死一次性约束** |
| **积分未购导致主结论缺席** | **项目无交付** | **主基准已改零依赖；11.1 给出逐项降级边界** |
| **free 模式结论被当作可交易结论** | **按一个连方向都不确定的数字做决策** | **11.2 的代码级闸门直接不产出该类指标；验收 #34** |
| **消融旁路改变候选规模** | **消融 leg 与基准不可比** | **主指标对持仓数不敏感；验收 #25 要求披露倍数** |
| **在 J 完成前跑出历史候选** | **结论衡量的是带 bug 的策略** | **11.0 写死前置；验收 #27 抽查分红季样本** |
| **配股标记召回率不足** | **高估收益的样本混入主指标** | **剔除率与数据侧实测事件数交叉核对（验收 #29）** |

### 13.1 回滚

- 阶段 0 四项修复各自独立带开关，可单独回滚。
- 回测侧为新增表与新增 `replay_mode`，不改动既有回测数据，回滚即停用。
- 重放引擎参数化保持默认行为不变，回滚为还原参数默认值。

## 十四、已确认决策

| 决策点 | 结论 |
| --- | --- |
| 研究目标 | 信号有效性，非组合收益模拟 |
| **核心定位** | **复用既有 `bottom_divergence_v2_*` 重放底座，只补研究层；不新建引擎** |
| 新建范围 | 仅三块：候选落库隔离、ST/行业历史化、策略无关编排入口 |
| 根因修复 | 止损解析改 setup 级共享函数；v3 的 `trade_plan` 对齐方案因循环依赖作废 |
| 观测单位 | **日历时间组合的正确构造：索引轴为持有日 d，持仓集合 `H(d,k)` 为 `[d-k, d-1]` 内发过信号的股票去重等权**。v4 的「按信号日算 k 日前向收益」是事件时间重叠构造，未消解时序重叠 |
| **主基准** | **市场中位数（零付费依赖）**。v4 定义在风格中性组上，会让主结论悬于付费数据；风格中性组降级为稳健性检验 |
| **主指标** | **`leg=strategy`、`k=5` 的日历时间组合收益 − 市场中位数组合收益** |
| **正控制** | **注入已知强度的合成信号做功效检验，给出「可检出的最小效应」**。v4 的 20 日动量在 A 股短周期多为反转，会给出错误信号 |
| **样本内外** | **2024+ 是样本内（策略实际开发期），2018–2023 是保留期**。v4 写反了。保留期亦非真样本外，报告须声明该边界 |
| **日组合表维度** | **主键 `(run_id, leg, holding_period_days, trade_date)`**；基准与 IC 移出本表 |
| **隔离回放** | **复制清单需扩展七张新表并改显式配置 + 启动自检**，现状硬编码六张表（`dataset.py:227-235`） |
| **指数读取源** | **必须切到 `index_daily`**。现状把指数当普通 code 存 `stock_daily`，`sh000001` 仅 464 行，2018–2023 无数据，属硬阻断 |
| 置信区间 | 仅由 moving block bootstrap 产生 |
| `n_eff` | **仅作披露诊断量，不参与区间计算**（v3 的二次缩放为错误） |
| **消融定义** | **判定器内部逐条件旁路（该条件不参与判定），并同步旁路排序权重**。v5 的「中性替代值」不成立——有序标签喂门限判定不存在中性值，结论完全由常量取值决定 |
| **持仓状态机** | **`H(d,k)` 由九态状态机决定，非「发过信号即持仓」**。`entry_blocked` 不计入（该类样本系统性偏向最强候选，计入即系统性高估）；`suspended` 计入且收益记 0 |
| **数据前置** | **依赖数据基础设施 J 而非仅 F**。F 只物化复权价，J 才让因子链路读它；J 前跑历史候选等于把除权假断层复制到全窗口 |
| **free 模式边界** | **只能支持「信号有无预测力」，不能支持可交易性结论**；由代码级闸门强制，不靠文档约定 |
| **配股** | **除权日前一交易日按收盘价强制平仓（`exit_rights`）**。v6 的「整条剔除」需追溯重算此前组合且使序列不可持有，已作废；受影响样本的 `forward_return_k` 标 `truncated_rights` 排除 |
| **逐日收益** | **首日 `close/open`、延续 `close/close`、出场 `open/close`，三段连乘等于 `open(T+1+k)/open(T+1)−1`**；基准用延续日公式且 `U(d)` 三条界定写死（8.2c） |
| **跌停顺延** | **成交价为下一可交易日开盘价，受阻当日亏损照实现** |
| **数据不可变** | **copy → hash → export → `run_data_manifest`；重放只读快照，可比性由 manifest 判定** |
| **模式闸门** | **代码级：free 模式下可交易性指标不产出，非仅标注；模式判定写入 manifest** |
| **free 偏差方向** | **不可知**。实测发现漏判（偏乐观）与误判（偏悲观）同时存在，v6 的「统一偏乐观」作废 |
| **算力** | **实测 82.4 小时串行**。因子计算必须与判定层解耦，一次计算供全部 leg 复用，否则十余条 leg 不可行 |
| **结论覆盖面** | **严格历史结论仅覆盖「L2 关闭」下的 L1/L3/L4/L5**；完整 L2 只能靠短期快照与前瞻跟踪，须写在报告首页 |
| **开工范围** | **数据 A0/A/B/G1/C + 回测阶段 0（含修复 5 个失败测试）可开工；阶段 2 及之后暂缓** |
| L5 | 无法消融，改为阶段间收益差异 + 标签打乱负控制 |
| 对照组 | 不使用被否决候选；行业匹配须用历史化行业 |
| 框架自检 | 正负控制是解读主结论的前置条件 |
| L2 主题层 | 历史重放默认关闭，开启结果仅作偏差上界 |
| T+1 | 入场用 T+1 开盘，k 日收益不含信号日当日 |
| 涨跌停 | **读 `daily_price_limit` 查表**，不做规则重建（规则本身时变，ST 历史化不足以修复）；入场受阻单独计数并报告占比；出场受阻顺延 |
| 停牌 | **读 `suspension_history` 判定**，不用 `gap_too_long` 启发式；穿透持有按交易日计；同时出具抑制口径作敏感性检验 |
| 退市 | 按最后可得收盘价清算并计入收益，不得丢弃 |
| 板块表隔离 | 默认复用 `isolated_replay_database`；方案 B 需成本实测支撑 |
| ST/行业历史 | `namechange` + `index_member_all`，均在 5000 积分档内 |
| 多重比较 | 主结论只认预先声明的单一主指标 |
| 分层分析 | 只做描述性，不做显著性断言 |
| 样本外 | 2024 年起为验证期，只跑一次 |
| 复权 | 全部用 `close_adj`；不可用区间拒绝出信号 |
| 重放产物 | 独立表，不写入生产 `screening_candidates` |
| 交付形态 | 首版 CLI 报告，不做 Web UI |
